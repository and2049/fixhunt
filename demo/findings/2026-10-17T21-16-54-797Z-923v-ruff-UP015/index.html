Rule analysis

Flags redundant 'r' mode argument in calls to built-in open().

Fix: Removes the second argument when it is exactly the string literal 'r' (single or double quoted).

8 hazards
  • Rewriting open(variable, 'r') may change behavior if variable is not a string but evaluates to a string at runtime, as the static analysis assumes the argument is the mode.
  • If open is imported via 'from io import open' or overridden in scope, removing the argument may call a different function with different defaults.
  • In Python 2, 'r' mode behaves differently regarding Unicode, so removal could change decoding behavior in hybrid environments.
  • If the call uses keyword arguments like open(file=file, mode='r'), the tool may not fire, but if it did incorrectly, removing the mode could break if other keyword arguments depend on its presence.
  • If the mode argument is a variable named 'r' in scope (e.g., r = 'wb'; open(f, r)), the tool should not fire, but a buggy implementation might mistake it for the literal 'r'.
  • If the open call is inside a lambda or comprehension evaluated later, removing the mode does not change behavior, but if the mode were dynamically constructed, static removal is unsafe.
  • If the file argument is omitted and relies on positional inference (e.g., open(mode='r')), the shape doesn't match the rule, but a faulty fix could break argument positioning.
  • Comments attached to the mode argument (e.g., open(f, 'r' # comment)) may be lost if the rewrite does not preserve trailing comments.
