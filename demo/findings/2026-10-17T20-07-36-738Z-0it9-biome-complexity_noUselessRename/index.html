Rule analysis

Flags when an imported, exported, or destructured binding is renamed to itself via `as`/`:` syntax.

Fix: Removes the redundant rename syntax (`as` or `:`) so the binding uses the original identifier directly, transforming `{ x as x }` → `{ x }`, `{ y: y }` → `{ y }`, etc.

1 hazards
  • In a destructuring pattern like `let { x: x } = expr;`, removing the colon changes nothing semantically but if `x` is also declared elsewhere in the same block, the rewrite could accidentally merge two distinct declarations if the tool incorrectly scopes the fix—though the rule only triggers on self-rename, the fix assumes no shadowing risk because the LHS and RHS names are identical, yet in nested blocks or with `var` hoisting, the visual removal might obscure that a declaration is happening (e.g., `var { x: x } = {x:1};` → `var { x } = {x:1};` still declares `x` correctly, but if the fixer operates on a snippet without full context, it might misapply in a `with` block where `x` refers to a property, though `with` is deprecated and the rule doesn’t fire there].
