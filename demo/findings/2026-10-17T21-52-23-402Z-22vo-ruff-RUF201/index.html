Rule analysis

The rule flags TOML configuration entries where Ruff lint selectors use numeric rule codes instead of human-readable rule names.

Fix: Replace each numeric rule code in select, ignore, extend-select, or extend-ignore lists with its corresponding human-readable rule name (e.g., 'F401' becomes 'unused-import').

12 hazards
  • The rewrite assumes all numeric codes have valid, stable name mappings; if a code is deprecated or misspelled, the fix may insert an invalid name causing configuration errors.
  • If the configuration uses variable references or expressions (e.g., select = [code]) instead of literals, the rule does not fire but the fix would incorrectly attempt to rewrite non-literal values.
  • Comments adjacent to or within the selector list (e.g., select = ["F401" # unused import]) may be lost or misplaced during the rewrite if the formatter does not preserve them.
  • The fix does not account for selective application per file or directory; replacing a global ignore like "C901" with its name may unintentionally disable the check in contexts where it was conditionally enabled via per-section overrides.
  • If the TOML file is parsed by a tool that expects numeric codes (e.g., a legacy script), replacing them with names could break external tooling that relies on the original format.
  • The rewrite changes the lexical form but not the semantic meaning only if the mapping is bijective and stable; however, Ruff may update name mappings in future versions, making today’s fix obsolete or incorrect.
  • In extend-select or extend-ignore, the fix may introduce duplicate names if the base configuration already includes the same rule via another path, potentially altering the effective lint set.
  • If the selector list contains a mix of codes and names (e.g., ["F401", "unused-import"]), the fix will rewrite only the codes, potentially creating redundancy or confusion.
  • The fix does not preserve whitespace formatting inside the array (e.g., newlines, indentation) beyond what the TOML formatter enforces, which may alter readability.
  • If the rule code is part of a larger string or interpolated value (not applicable in standard TOML but possible via preprocessor), the fix would not apply and could lead to inconsistent state.
  • Changing from codes to names may affect version control diffs in ways that obscure the intent of the change, especially if reviewers are unfamiliar with the naming convention.
  • The fix assumes the target Rust-based Ruff binary used for linting recognizes the rule names; if an older version is used, the names may be unrecognized, causing linting failures.
