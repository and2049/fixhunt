Rule analysis

Flags redundant else blocks after if statements containing breaking statements (return, break, continue, throw).

Fix: Removes the else block and places its statements directly after the if block, preserving their original order and indentation relative to the enclosing scope.

10 hazards
  • Moving statements from an else block after a continue in a loop changes which iteration they execute in, altering loop behavior.
  • If the else block contains a labeled break, moving it outside may break to a different label or become invalid.
  • Statements with side effects in the else block may now execute regardless of the if condition, changing program state.
  • If the else block declares a variable with let/const, moving it may alter its scope and cause temporal dead zone errors.
  • Comments attached to the else block may be lost or misplaced during the rewrite, affecting readability.
  • If the if block contains a return with a value, moving else statements after it creates unreachable code, potentially hiding logic errors.
  • In a switch case, moving else statements after a return may fall through to the next case if break is missing.
  • If the else block contains a throw, moving it after the if block may change the stack trace or exception handling context.
  • When the if block is inside a try block, moving else statements after it may place them outside the try's scope, altering finally execution.
  • If the else block contains a debugger statement, its execution context may change, affecting debugging behavior.
