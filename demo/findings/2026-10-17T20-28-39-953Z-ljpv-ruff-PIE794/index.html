Rule analysis

The rule flags duplicate field assignments within a class body where the same attribute name is assigned more than once.

Fix: The autofix removes all but the first occurrence of the duplicated field assignment in the class body, preserving the first definition and deleting subsequent duplicate lines.

12 hazards
  • Removing a duplicate assignment that had a side-effect (e.g., function call, I/O) changes program behavior by omitting that side-effect.
  • Deleting a duplicate assignment that mutated an object (e.g., list.append, dict.update) may leave the object in an unintended state if the mutation was meaningful.
  • Removing a duplicate assignment that relied on the prior value of the same variable (e.g., x = x + 1) alters the computation by using an outdated or undefined value.
  • Deleting a duplicate assignment that was intended to rebind a variable after a del statement may cause a NameError if the variable is used later.
  • Removing a duplicate assignment in a conditional block (if/while/for) may be incorrect if the indentation was misleading and the line was actually meant to be at class level.
  • Deleting a duplicate assignment that occurred after a comment may cause the comment to be orphaned or misattributed if the fix does not preserve comment placement.
  • Removing a duplicate assignment that was part of a chained assignment (e.g., a = b = expr) breaks the binding for the other target in the chain.
  • Deleting a duplicate assignment that was followed by a deletion (del) may cause the variable to be unbound when later code expects it to be defined.
  • Removing a duplicate assignment that was meant to override a parent class field may inadvertently preserve the parent's value, changing inheritance behavior.
  • Deleting a duplicate assignment that was syntactically valid but semantically dead (no further use) may still be hazardous if the line contained a macro-like side effect via import or decorator.
  • Removing a duplicate assignment that occurs before a try/except block may affect control flow if the assignment was guarding a variable used in the except clause.
  • Deleting a duplicate assignment that was the only source of a variable used in a nested function or lambda may cause a closure to capture an undefined variable.
