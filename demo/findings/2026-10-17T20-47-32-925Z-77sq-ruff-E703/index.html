Rule analysis

Flags statements ending with unnecessary semicolons.

Fix: Removes the trailing semicolon at the end of the statement, leaving the preceding code unchanged.

8 hazards
  • Rewriting 'x = 1;' to 'x = 1' changes nothing as the semicolon is purely syntactic and has no semantic effect in simple statements.
  • In compound statements like 'if True: pass;', removing the semicolon after the suite does not alter behavior because the semicolon only terminates the simple statement 'pass'.
  • For 'for i in range(10): print(i);', the semicolon after the loop body is irrelevant to execution and its removal preserves all side effects.
  • In function definitions like 'def f(): return None;', the trailing semicolon after the function body is ignored by the parser and its removal does not affect the function's behavior.
  • For class definitions like 'class C: x = 1;', the semicolon after the class suite is non-functional and deleting it does not alter class creation or attribute binding.
  • In import statements such as 'import os;', the semicolon is redundant and its removal does not affect the import mechanism or module availability.
  • For 'from sys import stdin;', the semicolon after the import statement is extraneous and deleting it preserves the imported name's availability.
  • In try-except blocks like 'try: pass; except: pass;', the semicolons after each suite are meaningless and their removal does not impact exception handling or control flow.
