Rule analysis

Flags ternary conditional expressions where the condition is negated (`not x`) and suggests swapping the arms to use the positive condition.

Fix: Swaps the true and false arms of the ternary expression and removes the `not` operator from the condition, transforming `b if not a else a` into `a if a else b`.

10 hazards
  • If `a` has side effects (e.g., a function call), evaluating it twice in the fixed form changes behavior compared to evaluating it once in the original.
  • If `a` is an expression with mutable state, re-evaluating it may yield different results due to state changes between evaluations.
  • If `a` raises an exception during evaluation, the fixed form may raise it where the original did not (or vice versa), altering control flow.
  • If `a` is not idempotent (e.g., `pop()` on a list), duplicating its evaluation changes program state incorrectly.
  • If `a` is a volatile expression (e.g., reading hardware or time), re-evaluation may produce inconsistent values.
  • If `b` or `a` contain comments, the autofix may discard them during AST reconstruction.
  • If the expression appears in a lambda or comprehension, duplicating `a` could affect scoping or closure capture unexpectedly.
  • If `a` is used for its truthiness but is later mutated, the fixed form may observe a different value than intended due to re-evaluation.
  • If `a` is a property with a setter, accessing it twice may trigger unintended side effects.
  • If the surrounding code relies on the exact evaluation count of `a` for logging, debugging, or performance reasons, the fix alters observable behavior.
