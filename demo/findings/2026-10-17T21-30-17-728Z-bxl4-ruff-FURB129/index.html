The rule flags iteration over the result of `readlines()` called on a file object within a for-loop.

Fix: Replace `fp.readlines()` with `fp` in the for-loop iterable, preserving whitespace and parentheses around the iterable expression.

8 hazards

  • If the file object `fp` is reassigned or mutated within the loop body, iterating directly on `fp` may reflect those changes during iteration, whereas the original code iterated over a static list from `readlines()`.
  • If `fp` is not a standard file object but a custom iterator where `__iter__` returns a fresh iterator each time, replacing `fp.readlines()` with `fp` could cause multiple iterations over the same underlying resource if the loop body re-iterates, leading to unexpected exhaustion.
  • If the `readlines()` call appears within a larger expression (e.g., a function call or tuple) inside the for-loop header, extracting only `fp` may break the syntax or alter the evaluated iterable.
  • If the loop variable (e.g., `line`) is used after the loop to access the last value, and the file is closed during iteration (e.g., via a `return` or `break` inside the loop), the behavior may differ because the list from `readlines()` retains all lines, while direct iteration may leave the file open or closed depending on timing.

  • If the file object is used elsewhere in the loop body (e.g., `fp.seek(0)`), switching to direct iteration may interfere with internal buffering or iteration state, causing skipped lines or infinite loops.
