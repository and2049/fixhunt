Rule analysis

Flags unnecessary concatenation of two or more string or template literals (including numbers converted via ToString) that can be safely merged into a single literal.

Fix: Replaces the concatenation expression with a single string or template literal where all parts are evaluated at compile time via ToString conversion and joined without alteration.

10 hazards
  • Rewriting `"" + obj` to `"` + String(obj)` changes behavior if obj has a custom toString or valueOf with side effects.
  • Concatenation involving a getter like `"" + obj.prop` may evaluate the getter once instead of twice if the property access is duplicated in the original.
  • If any part of the concatenation is a function call with side effects (e.g., `"" + f()`), moving it into a literal context does not remove the call, but the rule does not fire on such cases so this is not a direct hazard of the fix.
  • The fix assumes all operands are primitive-compatible at compile time; if an operand is a symbol, the original throws a TypeError but the fix would produce invalid output (though the rule does not flag Symbol concatenation).
  • In strict mode, evaluating `"" + undefined` produces the string "undefined", same as the fix, so no behavioral change there.
  • Template literals in the original may contain escaped characters (e.g., `"a\\b"`) that are preserved correctly in the fix, so no hazard from escaping.
  • If the concatenation is part of a larger expression (e.g., `("a" + "b") + c`), replacing only the inner part preserves grouping and evaluation order.
  • Comments adjacent to or inside the concatenation (e.g., `"a" /* comment */ + "b"`) are not moved by the fix and may be lost if the tool strips whitespace during rewrite.
  • Automatic semicolon insertion is unaffected because the fix does not alter statement structure or line breaks.
  • The fix does not introduce new variables or change scope, so hoisting and temporal dead zone behavior is preserved.
