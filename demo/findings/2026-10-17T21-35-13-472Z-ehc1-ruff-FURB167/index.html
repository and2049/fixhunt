Rule analysis

Flags usage of short-form regex flag constants like re.I in favor of their long-form equivalents like re.IGNORECASE.

Fix: Replaces each short-form regex flag (e.g., re.I, re.L, etc.) with its corresponding descriptive long-form constant (e.g., re.IGNORECASE, re.LOCALE, etc.) while preserving all other code structure and expressions.

12 hazards
  • Rewriting re.I inside a string literal like 're.I' would incorrectly modify code that is not executable, altering intended behavior.
  • If re is locally aliased (e.g., import re as regex), the fix may fail to match or incorrectly rewrite references, breaking flag resolution.
  • When the flag is used in a bitwise operation like re.I | re.L, rewriting only part of the expression could produce invalid syntax or incorrect flag combination.
  • If re.I is accessed via getattr(re, 'I'), the fix does not apply and may leave dynamic attribute access unchanged, missing the intent.
  • In a context where re is reassigned to a non-module object (e.g., re = 5), rewriting re.I would cause an AttributeError at runtime.
  • The fix may insert re.IGNORECASE in a position where a comment trails the short form (e.g., re.I # inline), potentially misplacing or deleting the comment due to whitespace handling.
  • If the short flag appears in a docstring or comment (e.g., "Use re.I here"), the fix could erroneously alter documentation, changing meaning without affecting execution.
  • When the flag is used as a string key in a dictionary (e.g., {'re.I': value}), rewriting it changes the key, breaking lookup logic that depends on the literal string.
  • In a lambda or comprehension where re is rebound locally (e.g., [re.I for re in range(5)]), the fix may misinterpret the loop variable as the module, leading to incorrect rewrites or errors.
  • If re.I is imported via from re import I, the fix does not trigger on the bare I and may miss the alias, leaving inconsistent usage.
  • The rewrite assumes re refers to the standard library module; if shadowed by a custom module with different attributes, the long form may not exist, causing AttributeError.
  • In Python optimizations or restricted execution modes where re.IGNORECASE is not defined (though unlikely), the fix could introduce a NameError where none existed before.
