Rule analysis

Flags redundant variable assignments directly before yielding the same variable.

Fix: Replace 'x = expr\n yield x' with 'yield expr', preserving indentation and removing the assignment line while keeping all other code unchanged.

12 hazards
  • Removing the assignment eliminates the local variable binding, altering the output of locals() inspection during generator suspension.
  • If the variable is referenced in a debugger or introspection tool at the yield point, the reference will become undefined after the fix.
  • The assignment may contain a side-effect (e.g., incrementing a counter via a property setter) that would be omitted by the fix.
  • If the assigned expression is used elsewhere in the function via closure capture, removing the assignment could break the closure by eliminating the variable reference.
  • The assignment line may carry a trailing comment that would be deleted by the rewrite, altering source documentation.
  • If the variable name is shadowed in an inner scope, removing the outer assignment could change which variable is yielded due to altered resolution.
  • The assignment may be part of a larger statement (e.g., walrus operator) that the rule does not handle, but if misapplied could break syntax.
  • If the expression is a mutable object and the variable is later mutated (though not yielded), the fix does not affect this, but the hazard is misdiagnosis—however, the rule only fires when unused, so this is mitigated; still, if the variable is used in a lambda defined later but not executed, the lambda's closure could break.
  • In rare cases, the assignment might be syntactically indistinguishable from a type annotation in stub files or conditional code, leading to incorrect removal.
  • If the yield is inside a try block and the assignment contains a finally-dependent expression, moving the expression into the yield could change exception timing.
  • The fix may interfere with instrumented code (e.g., coverage tools) that relies on the assignment line being executable.
  • If the assignment uses the walrus operator in a way that creates a variable used only in the yield, the rule may not fire due to current limitations, but if incorrectly extended, it could break.
