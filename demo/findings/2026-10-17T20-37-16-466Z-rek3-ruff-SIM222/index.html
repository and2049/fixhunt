Rule analysis

Flags 'or' expressions containing at least one truthy literal where the entire expression can be simplified to True (in boolean context) or shortened by removing trailing falsy-or-truthy terms after the first truthy term.

Fix: Replace the entire 'or' expression with True when used in a boolean context (if/while/assert/etc.), otherwise replace it with the first truthy operand (short-circuiting the rest).

10 hazards
  • The rewrite removes side effects from evaluating operands after the first truthy term, changing behavior if those operands have side effects (e.g., function calls, assignments).
  • In non-boolean contexts, replacing 'x or [1] or y' with 'x or [1]' alters the result when x is falsy but [1] is truthy and y is used elsewhere via aliasing or mutation.
  • If the first truthy term is a mutable literal like [1], replacing the expression with just that literal may cause unintended sharing if the result is stored and mutated later.
  • Removing trailing operands can break code that relies on those operands for their type or value in subsequent expressions (e.g., unpacking, indexing).
  • The fix may incorrectly remove parentheses that were grouping the 'or' expression with other operators, altering precedence.
  • Comments attached to removed operands (e.g., 'x or [1] # important') would be lost.
  • In boolean contexts, replacing with True is safe only if the original expression was guaranteed truthy; however, if the context expects a falsy value (e.g., in 'not (x or [1])'), the logic flips incorrectly unless the whole negated expression is handled.
  • If the 'or' expression appears in a default argument or lambda, early termination changes when default values are evaluated.
  • Replacing part of a larger expression (e.g., 'z = (x or [1]) + 5') with a subexpression may break if the original relied on the full expression's value for arithmetic or concatenation.
  • When the first truthy term is not a literal but a variable (e.g., 'x or flag or y'), the fix should not apply per rule intent, but if misapplied, it would incorrectly shorten the expression.
