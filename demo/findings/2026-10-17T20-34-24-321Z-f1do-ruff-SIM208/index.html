Rule analysis

Flags expressions containing two consecutive 'not' operators applied to the same subexpression.

Fix: Removes the outer 'not' and its surrounding parentheses if present, leaving only the inner expression after the inner 'not'.

10 hazards
  • Rewriting 'not (not x)' when 'x' is a property with a side-effecting __get__ method changes behavior because the property is accessed twice in the original but once in the fix.
  • If 'x' is a function call, the original evaluates it twice while the fix evaluates it once, altering side effects and performance.
  • When 'x' is an indexing operation like 'a[b]', the original may raise IndexError twice (if the first access succeeds but the second fails on a mutated object), whereas the fix only risks it once.
  • In 'not (not obj.method())', if 'method' returns a mutable object that changes state on first call, the second call operates on a different state than the fix assumes.
  • For 'not (not x)' where 'x' is a conditional expression like 'a if b else c', the original evaluates the condition twice, potentially observing different values if 'b' is mutable between evaluations.
  • If the inner 'not' applies to a comma-separated tuple like 'not (not (a, b))', removing the outer 'not' and parentheses alters the expression's structure and may break tuple display or unpacking expectations.
  • When the double negation appears inside a larger expression like 'f(not (not x))', the fix changes the number of times 'x' is evaluated, affecting side effects visible to 'f'.
  • If the code relies on the traceback depth for debugging or testing, removing the extra 'not' frame alters the call stack.
  • A comment placed between the 'not' tokens like 'not # comment (not x)' would be lost if the autofix removes the inner 'not' and whitespace without preserving comment placement.
  • In code using 'not (not x)' to deliberately force a boolean context (e.g., for truthiness testing in a numeric setting), the fix may change the type of the result in edge cases involving numpy arrays or custom __bool__ implementations.
