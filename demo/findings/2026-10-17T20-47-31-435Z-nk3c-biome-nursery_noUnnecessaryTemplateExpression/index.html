Rule analysis

Flags template literals containing only string literal interpolations that can be rewritten as concatenated or plain string literals.

Fix: Replaces the template literal with either a plain string literal if it has a single interpolation, or a string concatenation using + operator if it has multiple adjacent string literal interpolations, preserving original whitespace and quotes where applicable.

12 hazards
  • Rewriting `${'hello'}` to 'hello' changes behavior if the code relies on the template literal being a distinct object identity (e.g., for === comparison with another template literal).
  • Converting `${'a'}${'b'}` to 'a'+'b' may alter evaluation order if the original template was part of a larger expression where left-to-right timing mattered for side effects in surrounding expressions.
  • If the template literal appears in a context expecting a TemplateLiteral type (e.g., tagged template inference), replacing it with a string literal breaks type checking in TypeScript.
  • The autofix may incorrectly remove escaped characters like \n or \t within the string literals if they are present, altering the resulting string value.
  • When the template literal is immediately followed by a plus (+) without space, rewriting `'a'+'b'` could be misparsed as part of a larger concatenation chain due to operator precedence.
  • Comments inside the template literal (e.g., `${'hello' /* comment */}`) would be lost during the rewrite since string literals do not preserve internal comments.
  • If the string literal contains a line terminator (e.g., `${'a\nb'}`), rewriting it as a plain string literal may break if the surrounding code depends on the template literal's multi-line nature for ASI or parsing.
  • In strict mode, if the original template literal was used in an eval-like context, replacing it with a string literal could change how the string is interpreted due to differing escape handling.
  • The fix assumes all interpolated parts are pure string literals; if any interpolation is actually a non-literal (e.g., due to macro expansion), the rewrite would incorrectly remove necessary template syntax.
  • When the template literal is part of a sequence expression or comma operator, rewriting it may change how the expression is parsed or optimized by minifiers.
  • If the template literal is used as a property key in an object literal, rewriting it to a string literal may cause a syntax error if the original relied on template literal flexibility (though rare, as keys are coerced).
  • The autofix may insert unnecessary parentheses around the rewritten expression if not carefully formatted, potentially altering precedence in edge cases involving exponentiation or nullish coalescing.
