Rule analysis

Flags named or anonymous function expressions without 'this' usage or generator syntax that can be safely rewritten as arrow functions.

Fix: Replaces the function expression with an arrow function having the same parameters and body, preserving async if present, while maintaining identical lexical scope and binding behavior for non-this references.

10 hazards
  • Rewriting a function used as a constructor breaks instantiation because arrow functions lack [[Construct]] and throw when called with new.
  • If the function expression is referenced before its declaration via a different identifier, hoisting differences may cause ReferenceError where none occurred before.
  • When the function is a method in an object literal, the rewrite severs any implicit dependency on the function's name property for recursion or debugging, potentially breaking named function expression patterns.
  • If the function expression is wrapped in parentheses and immediately invoked, the arrow function rewrite may alter parsing due to tighter binding of => vs function in edge-case grammar contexts.
  • Comments attached to the function keyword or between parameters and body may be lost during the rewrite, as biome's autofix does not preserve arbitrary comment placement.
  • In TypeScript, if the function expression has a return type annotation inferred from context, the arrow function may trigger a type mismatch due to differing contextual typing rules.
  • If the function expression is part of a sequence expression or comma operator, replacing it with an arrow function could change operator precedence interpretation.
  • When the function expression is used as a getter or setter in an object literal, the rewrite fails silently because biome skips such cases, but if misapplied would violate ES accessor semantics.
  • If the function expression relies on arguments.callee for self-reference, the arrow function lacks both arguments and arguments.callee, breaking legacy introspection patterns.
  • In sloppy mode, if the function expression contains 'use strict' in its body, the arrow function inherits the outer strictness, potentially altering behavior if the outer scope is not strict.
