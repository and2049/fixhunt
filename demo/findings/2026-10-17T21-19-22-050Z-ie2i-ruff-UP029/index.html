Rule analysis

Flags imports of Python 3 builtins from compatibility modules like 'builtins' or 'six.moves' when they are unused after removing the import.

Fix: Removes the import statement and leaves all usages of the imported builtin unchanged, relying on the Python 3 builtin being available by default.

10 hazards
  • Removing 'from builtins import str' may break code if a local variable named 'str' was intended to shadow the builtin but the import removal causes the builtin to be used instead.
  • If 'six.moves.range' is imported and later reassigned to a non-callable, removing the import may cause a NameError when the builtin 'range' is used where a different object was expected.
  • The fix does not account for conditional imports; if the import is inside a function or conditional block, removing it may cause a NameError when the builtin is used outside that scope.
  • If the imported name is used as a string in eval() or exec(), removing the import may change behavior if the name resolution depends on the import being present.
  • Removing the import may break code that relies on the specific type or behavior of the shimmed builtin (e.g., 'past.builtins.map' returning a list in Python 2 style), even if the code is run on Python 3.
  • If the import is aliased (e.g., 'from six.moves import range as r'), the fix may not trigger or may leave the alias unused, but if it did, removing the import would break uses of the alias.
  • The fix may remove a comment attached to the import line (e.g., '# needed for old Python'), which is considered unsafe and could lead to loss of documentation.
  • If the module defining the shim (e.g., 'six') has side effects on import (e.g., registers plugins), removing the import may alter program behavior even if the imported name is not used.
  • In rare cases, if a third-party module defines a 'builtins' attribute that shadows the import, removing the import may cause a NameError due to missing attribute access.
  • If the code is run under a restricted environment where __builtins__ is modified, removing the import may bypass intentional builtin overrides provided by the shim.
