Rule analysis

Flags usage of `zip(dict.keys(), dict.values())` when iterating over both simultaneously.

Fix: Replace `zip(expr.keys(), expr.values())` with `expr.items()`, where `expr` is the same dictionary expression in both calls.

10 hazards
  • If `expr` has side effects (e.g., a function call), evaluating it twice in the original vs once in the fix changes behavior.
  • If `expr` is mutated between the `.keys()` and `.values()` calls, the zip may see inconsistent state while `.items()` sees a snapshot.
  • If `expr` is not a dict but a subclass with overridden `.keys()` or `.values()` that return non-corresponding iterables, the zip may pair incorrectly while `.items()` is correct.
  • If `.keys()` or `.values()` returns a custom iterator with state that affects iteration (e.g., depends on prior calls), replacing with `.items()` alters execution.
  • If the expression uses a walrus operator (e.g., `zip((d:=func()).keys(), (d:=func()).values())`), the fix would lose reassignment and break scoping.
  • If the code relies on the order of evaluation (e.g., `.keys()` has a side effect that must happen before `.values()`), the fix may reverse or eliminate ordering expectations.
  • If `expr` is a variable that gets rebound between the two attribute accesses (e.g., due to concurrency or descriptor magic), the fix uses a single consistent value while the original may see two different ones.
  • If the original code contains inline comments within the zip expression (e.g., `zip(d.keys() # comment, d.values())`), the fix may drop or misplace them during rewrite.
  • If `expr` is a property that returns a different dict on each access, the original zips keys from one dict with values from another, while the fix uses items from a single dict (possibly inconsistent).
  • If `expr` is `None` or an object that raises AttributeError on `.keys()` or `.values()` only under certain conditions (e.g., due to `__getattr__`), the fix may trigger the error earlier/later or not at all.

r1-p006 fix-changes-behaviorlabelled safejudge: real · high String Formatting Edge Cases

The fix replaces `zip(d.keys(), d.values())` with `d.items()`, but `zip` returns a reusable iterator while `dict.items()` returns a view that can be iterated multiple times. In the program, `zipped` is iterated once in the for-loop and then again in `list(zipped)`, so the original prints an empty list (iterator exhausted) while the fixed version prints the items again, changing the observable output.

d = {'a': 1, 'b': 2}

for k, v in zipped:
    s = f'{k!r}:{v!r}'
print(repr(list(zipped)))
