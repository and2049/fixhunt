Rule analysis

Flags calls to dict.fromkeys where the value argument is a mutable literal (list, dict, set).

Fix: Replaces dict.fromkeys(keys, mutable_value) with a dictionary comprehension {key: mutable_value for key in keys} to ensure each value is a distinct instance.

10 hazards
  • If 'keys' has side effects (e.g., a function call), evaluating it twice in the comprehension changes behavior.
  • If 'mutable_value' has side effects (e.g., a function call like []()), evaluating it per iteration changes behavior vs. single evaluation.
  • If 'keys' is not reusable (e.g., an iterator), the second iteration in the comprehension yields no items, resulting in an empty dict.
  • If 'keys' is used later in the code after being consumed by the comprehension, it may be exhausted and cause errors.
  • If the original code relied on all values being the same object (e.g., for identity checks or shared state), the fix breaks that assumption.
  • If 'mutable_value' is a type constructor (e.g., list), the comprehension calls it repeatedly, which is safe but may be less efficient than the original single call.
  • If the dict.fromkeys call is part of a larger expression, the rewrite may alter precedence or grouping, leading to syntax errors.
  • Comments attached to the dict.fromkeys line may be lost or misplaced during the rewrite.
  • If 'keys' contains duplicate elements, the comprehension processes duplicates while dict.fromkeys deduplicates, changing the resulting dictionary's keys.
  • If 'mutable_value' is a mutable object referenced elsewhere, the fix creates independent copies, breaking external aliases that expected shared mutation.
