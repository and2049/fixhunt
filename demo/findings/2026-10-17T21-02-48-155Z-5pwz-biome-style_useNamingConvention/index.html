Rule analysis

Enforces camelCase/PascalCase/CONSTANT_CASE naming conventions for all identifiers except those explicitly ignored.

Fix: Renames the identifier to comply with the applicable naming convention (camelCase for locals/parameters, PascalCase for types/classes/enums/namespaces, CONSTANT_CASE for module-level const/var, camelCase/PascalCase for imports/exports), preserving all other tokens and formatting exactly.

10 hazards
  • Renaming a variable referenced via `eval()` or dynamic property access breaks the reference because the string literal is not updated.
  • Renaming a function that is used as a constructor via `new window[oldName]()` changes behavior if the global property isn't updated.
  • Renaming a variable that closes over a function used in `setTimeout` creates a mismatch if the callback refers to the old name via closure or string.
  • Renaming a class that is extended via `eval('class extends ' + oldName)` breaks inheritance because the string lookup fails.
  • Renaming an enum member used in a bitwise operation like `flags & Enum.OldMember` silently changes semantics if the numeric value differs after rename (though Biome preserves value).
  • Renaming a variable in a with-statement scope (`with(obj) { x }`) may alter resolution if `obj` has a property matching the old or new name.
  • Renaming a function that is overridden in a derived class via string-based dispatch (`this[methodName]()`) causes the wrong method to be called if the string doesn't match.
  • Renaming an identifier that has a comment attached on the same line may detach or misplace the comment if the formatter doesn't preserve trailing comments during token replacement.
  • Renaming a variable that is named identically to a label (`label: while (label < 10) label++`) creates a conflict because the label and variable share the same name in different namespaces.
  • Renaming a private class field (if conventionally matched) that is accessed via `this[#field]` is invalid syntax—Biome doesn’t rename private fields, but if it did, it would break because `#` is not part of the identifier.

The fix renames class A_value to AValue, but the eval string concatenates Base.name at runtime to form 'class extends A_value {}'. After the fix, Base.name becomes 'AValue', so the eval produces a different class name and potentially a syntax error if the original name was expected, changing program behavior silently.
