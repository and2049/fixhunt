Rule analysis

Flags class definitions with empty parentheses when no base classes are specified.

Fix: Removes the empty parentheses following the class name when no base classes are present, preserving all other tokens and whitespace outside the parentheses range.

10 hazards
  • The rewrite may remove inline comments inside the parentheses, such as `class A(): # comment` becoming `class A: # comment`, altering comment placement relative to the class header.
  • If the parentheses contain a trailing comma like `class A(),`, the fix would incorrectly produce `class A:,` which is a syntax error due to dangling comma.
  • In Python 2, empty parentheses in class definitions could influence metaclass resolution implicitly; removing them might alter behavior in legacy code relying on old-style class semantics.
  • The fix does not account for parentheses used in type hints on the class line (e.g., `class A() -> None:`), where removing them breaks the return annotation syntax.
  • If the class definition is part of a larger statement via line continuation (e.g., `class A() \ : pass`), the fix may break syntactic structure by removing parentheses needed for line joining.
  • When the class header includes decorators (e.g., `@dec\nclass A():`), the fix operates correctly but may be misapplied if parentheses are mistakenly interpreted as part of the decorator expression.
  • The fix preserves surrounding whitespace but may alter formatting if the parentheses contained internal whitespace that was significant for alignment or readability in a team's style guide.
  • In code generated by tools or macros that rely on the exact token sequence `class A():` for pattern matching or replacement, the rewrite could break tooling expectations.
  • If the class is defined in a string or eval context (e.g., `eval('class A(): pass')`), the fix does not apply, but if applied manually, it would change the string content and thus the evaluated behavior.
  • The rewrite assumes the parentheses are solely for base classes; however, in rare cases involving experimental syntax or future-language parsers, empty parentheses might be reserved for other meanings, making removal forward-incompatible.
