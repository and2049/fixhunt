Rule analysis

Flags unnecessarily nested Literal types where inner Literals can be flattened.

Fix: Replaces nested Literal expressions with a single Literal containing all unique arguments from the inner Literals, preserving order of first occurrence and removing duplicates.

10 hazards
  • Rewriting Literal[Literal[expr]] where expr has side effects (e.g., function calls) changes evaluation from once per inner Literal to once in the flattened version, altering call count.
  • If inner Literals contain duplicate values, deduplication in the fix may break code relying on duplicate literal parameters for overload resolution or type narrowing.
  • Moving inline comments attached to inner Literal brackets (e.g., Literal["a" # comment ]) to the flattened Literal may detach them from their original syntactic context, changing comment association.
  • When nested Literals span multiple lines with trailing comments on some lines, the fix may reorder or lose those comments due to reformatting, violating the rule's noted unsafety condition.
  • If the outer Literal is used in a forward reference or string annotation, flattening may break evaluation if the inner Literals were relied upon for delayed processing.
  • In code that inspects the AST structure of Literal (e.g., via typing.get_args), the fix alters the nested structure expected by introspection tools or decorators.
  • If an inner Literal contains a mutable expression (e.g., Literal[[]]), though invalid, the fix would still flatten it, potentially exposing differences in how type checkers handle malformed literals.
  • When the nested Literal appears in a class body or function default, flattening could affect the timing of when the literal value is computed relative to other statements in the same block.
  • If the inner Literals are defined via imports or aliases that are later rebound, the fix captures their values at rewrite time, breaking dynamic behavior.
  • In code that uses Literal in conjunction with Final or ClassVar, flattening may interfere with how tools detect constantness if they rely on the Literal node structure.
