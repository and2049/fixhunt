Rule analysis

Flags `while 1:` loops and suggests replacing them with `while True:` for clarity.

Fix: Replace the literal integer 1 in the while condition with the boolean literal True, preserving all whitespace and formatting otherwise.

11 hazards
  • The rewrite changes the constant from int to bool, which could affect code that relies on the condition's type via type() or isinstance() checks.
  • If the loop condition is used in an expression elsewhere (e.g., assigned to a variable), the type change may break downstream logic expecting an integer.
  • In rare metaprogramming contexts where the AST node's constant value is inspected, the rewrite alters the observed value from 1 to True.
  • If the code is processed by tools that distinguish between 1 and True for optimization or serialization, the transformation may alter output.
  • Comments attached to the condition token (e.g., trailing comments on the same line) may be misplaced or lost during reformatting depending on the linter's formatting logic.
  • If the while statement is part of a larger compound statement parsed ambiguously, the rewrite could interfere with error recovery or parsing in malformed code snippets.
  • In code that deliberately uses 1 as a truthy integer for bitwise operations in the condition (though syntactically invalid as a standalone condition), the rewrite would not apply since such usage isn't a valid while condition.
  • The fix assumes the condition is a simple literal; if the condition were a more complex expression mistakenly parsed as '1' due to broken syntax, the rewrite could be incorrectly applied.
  • Changing 1 to True may affect debugging or introspection tools that display constant values in stack traces or frame locals.
  • If the code is run under a Python interpreter that treats 1 and True differently in edge cases (e.g., certain PyPy optimizations or sandboxed environments), behavioral differences could emerge.
  • In code that overrides the built-in True name in an outer scope (though irrelevant for the condition's evaluation), the rewrite might be misinterpreted as referencing the outer scope, though this does not change runtime behavior since True is resolved at compile time.
