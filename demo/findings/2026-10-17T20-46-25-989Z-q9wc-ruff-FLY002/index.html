Rule analysis

Flags str.join() calls where all arguments are simple variables or literals and suggests replacing them with equivalent f-strings.

Fix: Rewrites str.join(separator, iterable) into an f-string where each element from the iterable is placed literally separated by the separator, preserving order and literal separator content.

10 hazards
  • If any joined element is not a string, the f-string will invoke its __format__ method (default str) while str.join requires actual strings, potentially changing output or raising AttributeError.
  • If an element defines a custom __format__ that differs from its __str__, the f-string output will diverge from the join result.
  • If evaluating any element has side effects (e.g., function calls), the f-string evaluates them once during formatting, same as join, but if the join argument is an iterator consumed elsewhere, behavior may differ due to consumption timing.
  • If the separator contains replacement field syntax like '{' or '}', the f-string will interpret it as a format specifier, altering output or causing ValueError.
  • If the iterable is not a tuple/list (e.g., set, dict_keys), the f-string preserves iteration order but join may have used arbitrary order (for sets), leading to non-deterministic output changes.
  • If any element equals None, str.join raises TypeError while f-string converts it to 'None', changing behavior from exception to string output.
  • If the iterable is empty, both produce empty string, but if the separator is invalid in an f-string context (e.g., unbalanced braces), the f-string may raise ValueError where join succeeds.
  • Comments inside the join call parentheses or on the same line may be lost during rewrite, as the autofix replaces the entire expression without preserving internal comments.
  • If the join call is part of a larger expression and the f-string introduces unintended line breaks or changes precedence due to formatting, it could alter grouping.
  • If any element is an object with a __format__ method that returns non-string (e.g., bytes), the f-string result may be bytes while join expects strings, causing type errors downstream.
