12 hazards
  • The rewrite may incorrectly merge multiple noqa codes if the original line contains a trailing comma after the deprecated code, altering suppression intent.
  • If the noqa directive is split across multiple lines via backslash continuation, the rewrite may fail to match or corrupt the line structure.
  • In a line with multiple noqa codes separated by spaces (not commas), the rewrite may not match due to unexpected delimiter handling.
  • If the deprecated code appears as part of a larger identifier (e.g., in a string or comment), the rewrite could erroneously modify unrelated text.
  • When the noqa directive is embedded within a multiline string or docstring, the rewrite may break string syntax or introduce invalid escape sequences.
  • If the line contains a '#' character inside brackets or quotes (e.g., in a list or regex), the rewrite may mismatch the actual noqa directive due to incorrect comment detection.
  • The rewrite may remove or reorder inline comments that appear after the noqa directive on the same line, changing documentation or intent.
  • If the deprecated code is written with mixed case (e.g., 'pgh001'), the rewrite may not trigger due to case sensitivity, leaving the deprecated code unchanged.
  • In files with non-UTF-8 encoding, the rewrite may corrupt byte sequences when modifying the source, leading to decode errors.
  • If the noqa directive is the only content on a line and the rewrite changes its length, it may affect blank-line-dependent tools or formatters that rely on line count.
  • When the line ends with whitespace after the noqa directive, the rewrite may preserve or drop that whitespace inconsistently across editor configurations.
  • If the deprecated code is part of a larger noqa message (e.g., '# noqa: PGH001 some reason'), the rewrite may produce ambiguous or invalid code by replacing only the code portion.
