Rule analysis

Flags explicit default type arguments (`None`) for `Generator` and `AsyncGenerator` when they match the defaults introduced in Python 3.13.

Fix: Removes trailing type arguments that are exactly `None` for the second and/or third parameters of `Generator`, and the second parameter of `AsyncGenerator`, when they match the default values introduced in Python 3.13.

8 hazards
  • Rewriting `Generator[T, None, None]` to `Generator[T]` changes meaning if the code targets Python <3.13 where defaults are not applied.
  • If the annotation contains an inline comment (e.g., `Generator[int, None, None # comment]`), the fix may drop the comment, altering documentation.
  • In a string annotation like `"Generator[int, None, None]"`, the fix does not apply, but if incorrectly applied, it would corrupt the string.
  • If `None` is imported under an alias (e.g., `from types import NoneType as None`), the fixer might not recognize it as the default, leading to unsafe removal.
  • When used in a union like `Union[Generator[int, None, None], str]`, removing the `None`s could change the union's structure if relied upon for overload resolution.
  • In a forward reference evaluated later (e.g., in `TYPE_CHECKING` blocks), the rewritten form may resolve differently if the target scope lacks the updated built-in generics.
  • If the code uses a custom subclass of `Generator` that overrides `__class_getitem__`, the fix assumes standard library semantics and may be incorrect.
  • When the annotation is part of a larger expression (e.g., in a `Callable[[], Generator[int, None, None]]`), the fix only applies to the nested annotation and must not disturb the outer structure.
