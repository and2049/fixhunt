Rule analysis

Flags unnecessary `pass` or ellipsis (`...`) statements when they appear alongside any other executable statement in a function, class, or block.

Fix: Removes the unnecessary `pass` or ellipsis (`...`) statement when it occurs in a block containing at least one other statement.

8 hazards
  • Removing a `pass` after a string literal may cause that string to be interpreted as a docstring, altering the function or class's `__doc__` attribute.
  • If a `pass` or `...` is followed by a commented-out line that relies on indentation, removing it could shift the comment's block association.
  • In a `try` block, removing a `pass` may change which `except` clause catches an exception if the block structure is altered by comment reattachment.
  • If the `pass` or `...` is the last line in a function and is followed by a blank line containing a trailing comment, removing it could move that comment into the preceding line's visual scope.
  • In an `async` function, removing a `...` placeholder does not affect coroutine behavior but may mislead tools that infer stub status from ellipsis-only bodies.
  • If a `pass` appears in a class body and is removed, subsequent assignment statements may be promoted to class attributes earlier than intended during execution.
  • In a nested block like an `if` inside a `for`, removing a `pass` could alter the `else` clause's execution if the block's nesting is visually misparsed due to comment shifts.
  • If a `# type: ignore` comment sits on the same line as the `pass` or `...`, removing the placeholder may detach the ignore from its intended target, suppressing or exposing type errors incorrectly.
