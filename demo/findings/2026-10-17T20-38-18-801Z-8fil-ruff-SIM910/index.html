Rule analysis

Flags dict.get() calls where the second argument is explicitly None.

Fix: Removes the ', None' argument from dict.get() calls, leaving only the key argument.

8 hazards
  • If the call includes a trailing comment after the closing parenthesis, the comment may be lost during rewrite.
  • If the default argument is a complex expression with side effects (though None has none), removing it could alter evaluation order in hypothetical extended cases.
  • In code where None is used as a sentinel value distinct from the key's absence, removing it could change logic if the default were ever non-None (but rule only triggers on None).
  • If the get call is part of a larger expression where the parentheses affect grouping, removing arguments could alter precedence (unlikely but possible in nested calls).
  • If the dictionary get is overridden in a subclass where the default parameter has special meaning beyond the built-in, the fix assumes standard behavior.
  • If the code relies on the explicit None for documentation or clarity, removing it reduces expressiveness (semantic hazard).
  • If the line contains irrelevant whitespace formatting that the rewrite alters, it might affect tools sensitive to exact formatting.
  • If the get call is generated by a macro or codegen tool that expects the two-argument form, rewriting could break tooling expectations.
