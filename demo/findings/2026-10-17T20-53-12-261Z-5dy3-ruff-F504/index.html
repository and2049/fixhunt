Rule analysis

Flags printf-style formatting expressions where extra named keys appear in the mapping argument but have no corresponding placeholder in the format string.

Fix: Removes all key-value pairs from the mapping argument where the key does not appear as a named placeholder in the format string.

12 hazards
  • Removing a key whose value is a function call (e.g., func()) eliminates its side effects, changing program behavior if the function performs I/O or mutates state.
  • If the mapping argument is a variable (not a literal), the fix incorrectly assumes it can be rewritten as a smaller literal, which fails when the variable is reused elsewhere or has dynamic contents.
  • When the format string contains duplicate placeholders (e.g., '%(a)s %(a)s'), removing a key that appears only once in the mapping but is referenced multiple times may still be safe, but the fix logic must not overremove; however, the rule does not fire in such cases because the key is used.
  • If the mapping argument is constructed via a function call (e.g., % build_dict()), the fix cannot safely rewrite it to a literal without knowing the function's output, potentially causing a mismatch between expected and actual keys.
  • If the mapping argument includes nested expressions like %(key)s % {'a': f().b}, removing the key may break attribute access if f() returns None or an unexpected type, though this is less common.
  • Comments attached to the removed key-value pairs (e.g., # TODO) are lost when the fix rewrites the dictionary literal, stripping inline documentation.
  • In Python versions prior to 3.6, dictionary literals preserve insertion order only as an implementation detail; removing keys may alter iteration order if the dict is later passed to code relying on order (e.g., for k, v in d.items(): ...)
  • If the mapping argument is used in a larger expression (e.g., (%(a)s) % {'a':1, 'b':2} + c), the fix rewrites only the dict part, but if the surrounding expression depends on the exact structure (e.g., len(...) or == comparison), behavior may change.
  • When the format string uses mixed formatting (e.g., '%(name)s %d' % ({'name': 'x', 'extra': y}, 42)), the fix incorrectly assumes the entire right-hand side is a mapping, leading to invalid syntax or TypeError.
  • If the mapping argument is a subclass of dict that overrides __missing__ or __getitem__, removing keys may change behavior if the code relies on the fallback mechanism for missing keys.
  • The fix may produce a dictionary with fewer keys than expected by subsequent code that inspects the argument (e.g., via locals() or vars()), breaking introspection or debugging logic.
  • In rare cases, removing a key could resolve a naming conflict in a comprehension or lambda scope if the key was accidentally shadowing a built-in, though this is highly speculative and context-dependent.
