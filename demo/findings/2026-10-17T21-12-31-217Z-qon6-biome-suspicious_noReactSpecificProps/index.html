Rule analysis

The rule flags any JSX attribute named 'className' as a React-specific prop that should be replaced with 'class'.

Fix: Replace every occurrence of the JSX attribute name 'className' with 'class', preserving the attribute's original value (including expressions, strings, or JSX spread) and all other attributes, whitespace, and formatting.

8 hazards
  • Rewriting 'className' to 'class' in a JSX element that is actually a React component will cause the prop to be ignored, breaking styling or behavior that relies on the React-specific prop.
  • If the JSX element is part of a higher-order component or factory that expects a 'className' prop internally (e.g., for forwarding), renaming it to 'class' will prevent the prop from being received, leading to missing styles or logic.
  • In frameworks like Solid or Qwik, if a component uses 'className' as a local variable or state alias (e.g., via destructuring), the rewrite could incorrectly attribute the JSX attribute to a variable scope, causing a reference error.
  • When 'className' is used with a spread operator (e.g., <div {...props} className="extra" />), the fix only renames the explicit attribute; however, if props contains a 'className' field, the spread may still pass it through, resulting in duplicate or conflicting attributes depending on the framework's attribute merging behavior.
  • If the JSX appears inside a string literal, template literal, or JS comment (e.g., const msg = '<div className="box"></div>'; or {/* <div className="box" /> */}), the tool must not modify it, but a flawed implementation might erroneously rewrite the text, corrupting the string or comment content.
  • If the 'className' attribute contains a value with side effects (e.g., className={getClass()}), the rewrite preserves the value, but if the framework treats 'class' differently (e.g., as a signal or reactive property), the timing or tracking of the side effect may change.
  • In SVG elements, while 'class' is valid, some older SVG parsers or tools might expect 'className' for compatibility; renaming to 'class' could break tooling or CSS selector matching in edge cases involving SVG-specific CSSOM access.
  • If the JSX element is dynamically generated via a function that returns a string containing 'className' (e.g., return `<div className="${cls}">`;), the rule does not apply because it's not JSX, but if misapplied, it would corrupt the template string.
