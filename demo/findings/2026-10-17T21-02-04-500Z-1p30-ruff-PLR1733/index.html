Rule analysis

The rule flags dictionary index lookups using the loop variable when iterating over .items() where the corresponding value is already available.

Fix: Replace the dictionary index lookup d[key] with the already available loop variable value that corresponds to the value in the iteration.

10 hazards
  • Rewriting d[k] to v changes behavior if the loop variable v is reassigned later in the loop body, as the original code would re-read the current dictionary value while the fix uses the stale local variable.
  • If the dictionary d is mutated during iteration (e.g., keys added/removed), the original d[k] may raise KeyError or reflect updates, whereas the fixed v refers to the value at iteration start and avoids such errors or misses them.
  • When d is not a standard dict but a custom mapping with __getitem__ side effects (e.g., logging, state changes), replacing d[k] with v omits those effects.
  • If k or v is used elsewhere in an outer scope and the rewrite alters which variable is referenced due to name collision or shadowing, the fix may incorrectly bind or use the wrong variable.
  • The fix may remove a necessary del or reassignment to d[k] if the lookup was part of a larger expression involving assignment or deletion, altering mutability intent.
  • If the dictionary value accessed via d[k] is a mutable object and the code relies on retrieving the latest reference (e.g., after in-place mutation elsewhere), using v may refer to an outdated object if the dictionary was updated and the loop variable not refreshed.
  • Comments attached to the d[k] expression may be lost if the autofix replaces the entire expression without preserving inline or trailing comments.
  • In nested loops where inner loop variables reuse k or v names, the fix may incorrectly resolve to an inner loop variable instead of the intended outer one, altering semantics.
  • If the dictionary access d[k] occurs in a context where its type is used for overload resolution or generic specialization (e.g., in templating or generic functions), replacing it with v may alter inferred types and break type checking.
  • When d[k] is used in a default argument or lambda capture within the loop, the timing of evaluation shifts from lookup-time to loop-entry-time, potentially capturing different values if the dictionary mutates.
