Rule analysis

Flags consecutive 'global' or 'nonlocal' statements declaring separate variables when they could be combined into a single statement.

Fix: Replaces consecutive 'global' or 'nonlocal' statements with a single statement that combines all declared variables into a comma-separated list, preserving the order of appearance.

8 hazards
  • Moving a 'global' statement after a comment would detach the comment from the statement, altering readability and potentially meaning if the comment was intended as documentation for that specific declaration.
  • If a 'global' statement is followed by an inline comment on the same line, the fix would drop that comment because it only preserves comments on separate lines before the first statement.
  • When 'global' and 'nonlocal' statements are interleaved, combining them into one statement is invalid syntax because 'global' and 'nonlocal' cannot be mixed in the same statement.
  • If a variable name appears in both a 'global' and a subsequent 'nonlocal' statement (or vice versa), combining them would create a conflicting declaration that is invalid in Python scope rules.
  • Placing a combined 'global' statement before other statements that use those variables could change behavior if the original separate statements were guarded by a conditional that executed later, though this is prevented by the rule requiring consecutive statements.
  • If the block contains a nested function that references the same variable name, moving the declaration via combining statements does not affect scoping because 'global'/'nonlocal' apply to the entire function scope regardless of position.
  • In rare cases where a 'global' statement is used to override a built-in and the order of overriding matters for side effects in imported modules, combining statements does not change the order since all declarations happen simultaneously at function entry.
  • If a 'global' statement is split across multiple lines using backslash continuation, the fix would not apply because the rule only detects simple statement lines, so no hazard arises from the fix itself in such cases.
