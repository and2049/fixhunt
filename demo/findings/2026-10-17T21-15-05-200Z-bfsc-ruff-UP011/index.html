Rule analysis

Flags redundant parentheses when using @functools.lru_cache() without arguments.

Fix: Removes the trailing empty parentheses from @functools.lru_cache(), rewriting it as @functools.lru_cache while preserving spacing, imports, aliases, and surrounding decorators.

12 hazards
  • Rewriting @functools.lru_cache() inside a TYPE_CHECKING block may break type checking if the block is conditionally excluded at runtime but the linter assumes it is active.
  • If the decorator line contains a trailing comment after the parentheses, the fix may drop or misplace that comment during whitespace normalization.
  • When the decorator is applied to a class, removing parentheses could be misinterpreted if the class defines __call__ and the decorator is later invoked elsewhere in the module.
  • In code that manually inspects decorator syntax via ast or inspect, the absence of parentheses may alter the perceived call structure and break introspection logic.
  • If functools.lru_cache is shadowed by a local variable named lru_cache in an outer scope, the unqualified name after rewrite may resolve incorrectly.
  • When the decorator is used on a forward-referenced name in a string annotation context, the rewrite has no effect but may create inconsistency in mixed-style codebases.
  • If the line contains a line continuation character within the parentheses (e.g., due to formatting), removing them may break the syntactic validity of the statement.
  • In Python versions prior to 3.8, removing the parentheses would cause a SyntaxError because lru_cache could not be used as a bare decorator.
  • If the decorator is part of a macro-generated code block where the parentheses are significant for template matching, their removal may prevent correct expansion.
  • When the decorator appears in a stub (.pyi) file, some type checkers may expect the explicit call form for compatibility with older stubs, and the rewrite could trigger false positives.
  • If the decorator line is edited via a tool that relies on the presence of parentheses to delimit the decorator expression, subsequent edits may fail to parse correctly.
  • In rare cases where lru_cache is imported via a relative import or through a namespace package, the rewrite does not affect resolution but may obscure intent in code review.

r2-p005 fix-changes-behaviorlabelled safejudge: real · medium AST introspection of decorator call structure

The fix removes the parentheses from @functools.lru_cache(), changing the AST node type from a Call to an Attribute. The program uses ast.parse to inspect its own source and expects decorator nodes to have 'args' and 'keywords' attributes, which only exist on Call nodes. After the fix, the Attribute node lacks these attributes, causing an AttributeError and changing the exit code from 0 to 1.
