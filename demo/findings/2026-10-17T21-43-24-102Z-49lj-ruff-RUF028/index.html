Rule analysis

Flags formatter suppression comments (`fmt:` or `yapf:`) placed where they have no effect on formatting.

Fix: Removes the ineffective formatter suppression comment line entirely, leaving surrounding code and other comments unchanged.

10 hazards
  • Removing a `# fmt: off` comment may allow the formatter to reformat subsequent code, changing its layout but not its semantics.
  • Removing a `# fmt: on` comment may cause the formatter to continue suppressing formatting beyond the intended region, altering code style inconsistently.
  • Removing a `# fmt: skip` comment may cause the formatter to reformat the immediately following line, potentially changing its appearance.
  • Removing a `# yapf: disable` comment may allow YAPF (if used) to format code that was previously excluded, affecting formatting only.
  • Removing a `# yapf: enable` comment may cause YAPF to remain disabled for subsequent code, leading to inconsistent formatting if YAPF is active elsewhere.
  • If the suppression comment is the only content on a line, its removal may delete a blank line that was intentionally used for visual separation, affecting readability.
  • If the suppression comment shares a line with other code (e.g., after a statement), the fix does not apply because the rule only triggers on full-line comments—this hazard does not occur under correct rule application.
  • In rare cases, removing a comment could affect tools that parse comments for metadata (e.g., docstring extractors, linters), though standard Python execution ignores comments.
  • The fix does not alter AST structure or runtime behavior, as comments are stripped during parsing and have no semantic meaning.
  • If the comment is part of a multi-line string or tokenized incorrectly due to encoding issues, removal might alter tokenization—but this is irrelevant as the rule only targets syntactically valid comment lines.
