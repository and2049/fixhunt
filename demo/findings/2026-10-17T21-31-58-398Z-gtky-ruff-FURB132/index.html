Rule analysis

Flags conditional removal via 'in' followed by .remove() where discard() would suffice.

Fix: Replace the conditional block checking membership and calling .remove() with a direct call to .discard() on the same set with the same argument.

12 hazards
  • The condition may have side effects (e.g., function calls) whose execution is skipped when replacing with discard(), altering program behavior.
  • If the set expression is complex (e.g., a function call), evaluating it once in discard() vs. twice in the original (in condition and remove) changes evaluation count and potential side effects.
  • The variable used in the condition and remove might be reassigned or aliased between the check and the removal, making discard() operate on a different value.
  • If the set is a property or item access (e.g., obj.attr or arr[idx]), the fix may change how many times the attribute/index is evaluated.
  • The original code may rely on the KeyError being raised for debugging or control flow when the element is absent, which discard() suppresses.
  • If the set is actually a frozenset or other immutable set-like type, discard() may not exist or behave differently, causing AttributeError.
  • The fix may remove necessary comments or formatting attached to the if statement or its body that are not preserved in the rewrite.
  • In nested scopes, the variable names might refer to different entities due to shadowing, and the fix does not re-resolve them in the new context.
  • If the set is accessed via a descriptor (__getitem__/__setitem__) with logging or validation, discard() bypasses the intermediate check logic.
  • The rewrite assumes the argument to remove is hashable and valid for discard; if it is unhashable, both fail, but the error type or message might differ slightly in edge cases.
  • If the set variable is reused later and the conditional removal was part of a larger state-dependent logic, discarding unconditionally may break invariants.
  • The fix may interfere with debugger breakpoints set on the if line or the remove line, altering debugging experience.
