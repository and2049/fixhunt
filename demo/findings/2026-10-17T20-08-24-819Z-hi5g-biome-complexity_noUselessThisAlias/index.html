Rule analysis

Flags unnecessary aliases to 'this' when used only within arrow functions that inherit the outer 'this'.

Fix: Removes the variable declaration and replaces all references to the aliased variable with 'this'.

10 hazards
  • If the alias variable is reassigned after its initial assignment, replacing references with 'this' will use the current 'this' value instead of the captured value, changing behavior.
  • If the alias variable is used in a nested function that is not an arrow function (e.g., regular function or eval), the replacement may break due to differing 'this' binding.
  • If the alias variable is used outside the scope where it was declared (e.g., returned or closed over in a way that escapes), removing the declaration causes a ReferenceError.
  • If the alias variable name conflicts with a variable in an inner scope, removing the outer declaration may cause inner references to resolve to a different variable.
  • If the alias variable is used in a dynamic context like 'with' or indirect eval, static replacement cannot accurately determine usage, leading to incorrect refactoring.
  • If the alias variable is declared with 'var' and hoisted, removing it may affect the temporal dead zone or hoisting behavior in ways that change execution if referenced before declaration.
  • If the alias variable is part of a comma-separated declaration (e.g., 'const self = this, other = expr;'), the fix may incorrectly remove the entire declaration or mishandle the separator.
  • If the alias variable is used in a type annotation or JSDoc comment (e.g., '/** @type {Any} */ const self = this;'), removing the declaration may strip useful type information.
  • If the alias variable is used in a destructuring pattern or default parameter, the simple replacement fails to account for complex binding structures.
  • If the alias variable is referenced in a string literal (e.g., for code generation or logging), textual replacement is not performed, leading to mismatches between code and strings.

Findings

r1-p007 fix-changes-behaviorlabelled safejudge: real · high Var hoisting and TDZ interaction

The fix removes a `var _this = this` declaration and replaces a reference to `_this` with `this`, but the reference occurs before the declaration in the same function scope. Due to hoisting, the original code reads the uninitialized variable (yielding `undefined`), while the fixed code reads the function's `this` binding (yielding the called object). This changes observable behavior in valid JavaScript and the fix is not safe for this construct.
