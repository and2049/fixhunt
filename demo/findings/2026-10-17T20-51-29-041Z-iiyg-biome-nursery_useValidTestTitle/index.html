Rule analysis

The 'useValidTestTitle' rule flags test block calls where the title argument is missing, non-string/literal, or has leading/trailing whitespace.

Fix: Replaces the invalid title argument with a trimmed string literal if it is a string or template literal; otherwise removes the argument entirely, preserving all other arguments and formatting.

10 hazards
  • Rewriting a non-literal title (e.g., a variable) to a string literal changes runtime behavior if the title was dynamically computed.
  • Removing a non-literal title argument shifts subsequent arguments left, potentially causing a function to receive an unexpected value (e.g., a callback becoming the title).
  • If the title is a template literal with side effects (e.g., `${fn()}`), removing it eliminates those side effects.
  • Trimming whitespace in a title that is intentionally used for visual alignment or formatting in test output alters test reporting aesthetics.
  • If the title is part of a larger expression (e.g., concatenation), replacing it breaks the expression and may cause syntax errors.
  • When the title is omitted and the rule inserts a blank string, some test frameworks may treat blank titles differently than missing titles (though rare).
  • Comments attached to the title argument (e.g., /* title */ " foo" ) may be lost during replacement if the tool does not preserve them.
  • In nested test blocks, altering a parent suite's title may affect how child tests are grouped or reported in hierarchies.
  • If the title is a tagged template literal, replacing it with a plain string loses the tag's semantic meaning and any custom processing.
  • Changing a title from a string containing only whitespace to an empty string may affect tests that rely on title length for conditional logic (highly unconventional but possible).
