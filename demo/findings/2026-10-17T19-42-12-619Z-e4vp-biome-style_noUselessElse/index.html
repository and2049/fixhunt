2026-10-17T19-42-12-619Z-e4vp-biome-style_noUselessElse · fix labelled safe · 16 programs, 14 fired, 14 fixed, 3 oracle-backed finding(s) · model cost $0.0538

Rule analysis

Flags else blocks that follow an if block containing a breaking statement (return, break, continue, throw), as they are unreachable and redundant.

Fix: Removes the else block and places its statements directly after the if block, preserving their original order and indentation relative to the function or block scope.

10 hazards
  • Moving a break statement out of a switch case alters fall-through behavior, potentially executing unintended cases.
  • Relocating a continue statement may cause it to target an outer loop instead of the innermost one, changing iteration behavior.
  • Hoisting a function declaration from within the else block could make it available earlier than intended, causing premature invocation.
  • Moving a variable declaration with let/const from the else block risks referencing it before initialization if used prior to the if block.
  • Extracting a labeled statement from the else block may break label targeting if the label is referenced elsewhere via break/continue.
  • Relocating a throw statement could change the stack trace by altering the point of origin, affecting error handling logic.
  • Moving a return statement from within a try block may skip execution of a finally block that was meant to run regardless.
  • Duplicating a side-effecting expression (e.g., a function call) from the else block into multiple paths due to code duplication during refactoring is not applicable here, but the fix assumes single occurrence—however, if the else block contains multiple statements, their relative order is preserved but their execution context changes.
  • If the else block contains a debugger statement, moving it may alter developer tooling behavior if the surrounding scope has different blackboxing settings.
  • Comments attached to the else brace or internal to the else block may be lost or misplaced during the rewrite, degrading code readability.

r1-p007 fix-changes-behaviorlabelled safejudge: real · high Premature function hoist

The fix hoists a function declaration out of an else block that is never executed because the preceding if block always returns. In the original code the declaration is dead code so f is never created and the call throws a ReferenceError; after the fix the declaration becomes live, f is defined, and the program prints 1. This is a silent change in observable behavior for a plausible construct.

r2-p001 fix-breaks-syntaxlabelled safejudge: real · high Shadowing after removal of else block

The fix removes the else block but leaves its body at the same scope level, causing the inner 'let x = 2' to conflict with the outer 'let x = 1'. In the original code the else block created a nested block scope so the redeclaration was legal; after the fix both declarations are in the same function scope, producing a syntax error. This is a silent correctness bug for any code that shadow-declares a variable inside the else branch.
