Rule analysis

The rule flags calls to Number.prototype.toFixed() without arguments, as they rely on the implicit default of 0 digits after the decimal point.

Fix: The autofix adds the argument `0` to the call, transforming `toFixed()` into `toFixed(0)`.

1 hazards
  • If `toFixed` is a non-standard method overridden on an object, adding an argument may cause a TypeError if the custom implementation does not accept arguments. If the call is part of a larger expression, inserting the argument could alter parsing due to operator precedence, especially if the call is used in a context like `a + b.toFixed()` where semicolon insertion or binding might be affected. If the original code relied on implicit semicolon insertion and the fix introduces a syntax error by breaking ASI boundaries (e.g., if the line ends with `toFixed()` and the next line starts with a `[` or `(`, adding `(` changes the interpretation). If the call appears inside a template literal or tagged template, the added parentheses or comma could interfere with the template’s grammar. If the method is accessed via a property that has a getter with side effects, evaluating the property twice (once for the original call and once during fix application in a faulty tool) could cause unintended behavior—though the fix itself doesn’t re-evaluate, unsafe tooling might. If the code uses `toFixed` in a context where the return value is ignored but the call is made for its side effects (e.g., in a custom proxy), adding an argument might trigger different trap behavior. If the code is minified or relies on specific formatting, the fix could break formatting-dependent tools or preprocessors. If the call is in a legacy JavaScript environment where `toFixed` behaves differently with explicit arguments (e.g., older engines), the fix might not be equivalent.
