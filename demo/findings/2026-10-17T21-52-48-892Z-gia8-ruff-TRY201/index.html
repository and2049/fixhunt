Rule analysis

Flags unnecessary repetition of caught exception variable when immediately re-raising the same exception.

Fix: Removes the exception variable name from both the except clause and the raise statement, changing 'except X as var: raise var' to 'except X: raise'.

10 hazards
  • The exception variable is used after the raise in the same block, so removing it causes an undefined variable error.
  • The exception variable is reassigned between the except and raise, so the fix alters which object is raised.
  • The exception variable is referenced in a nested function defined between except and raise, capturing the original binding which the fix removes.
  • The except clause contains multiple exception types (e.g., 'except (ValueError, TypeError) as exc') and the fix incorrectly drops the variable.
  • A comment attached to the 'as exc' token is lost during the rewrite.
  • The raise statement is inside a finally block where the variable is referenced from an outer scope, and the fix breaks that reference.
  • The exception variable name shadows a global or nonlocal variable, and removing the binding changes later accesses to that variable.
  • The except block is empty except for the raise, and removing the variable leaves a pointless 'except:' that may confuse readers but is syntactically valid.
  • The code relies on the exception variable being deleted after the block (via implicit cleanup), and altering the binding scope changes deletion timing.
  • The raise statement is modified by a decorator or metaclass that inspects the source, and the rewrite changes its behavior.
