Rule analysis

Flags simple assignments where the target variable appears on the left-hand side of a binary operation on the right-hand side, suggesting replacement with an augmented assignment.

Fix: Replaces the assignment statement with an augmented assignment using the same operator (e.g., 'x = x + 1' becomes 'x += 1'), preserving the left-hand side target and the right-hand side operand excluding the target.

10 hazards
  • For mutable targets like lists, the rewrite changes semantics by mutating the original object in-place, affecting all aliases (e.g., 'foo = foo + [2]' vs 'foo += [2]' when other variables reference the same list).
  • For immutable targets like strings, the rewrite may be semantically invalid if the target is not the left operand (e.g., 'x = "prefix-" + x' cannot be safely rewritten as 'x += "prefix-"' due to non-commutativity).
  • If the right-hand side contains side effects (e.g., function calls), the rewrite may alter evaluation order or frequency (though PLR6104 typically avoids such cases, complex expressions might still pose risks if misidentified).
  • For numeric types with user-defined __add__ or __iadd__ methods, the rewrite may invoke different methods, leading to divergent behavior if the methods are not equivalent.
  • In NumPy arrays, augmented assignment may fail due to shape or dtype constraints where the plain assignment succeeds via broadcasting or promotion (e.g., in-place multiplication requiring matching shapes).
  • The rewrite removes any inline comments present in the original statement, as the entire line is replaced.
  • If the left-hand side is a complex target (e.g., attribute or subscript), the rule may not fire, but if it did incorrectly, the rewrite could misinterpret scoping or evaluation (e.g., 'self.x = self.x + 1' is safe, but misfiring on non-simple targets could break).
  • For targets that are not simple names (e.g., tuples or destructuring), the rule does not apply, but if erroneously triggered, the rewrite would be syntactically invalid.
  • If the assignment is part of a larger statement (e.g., in a loop or conditional), the rewrite preserves structure but may affect debugging or profiling tools that rely on exact line numbers or bytecode.
  • In rare cases involving descriptors or properties with __set__, the augmented assignment may trigger __iadd__ directly, bypassing __set__ and altering expected behavior.
