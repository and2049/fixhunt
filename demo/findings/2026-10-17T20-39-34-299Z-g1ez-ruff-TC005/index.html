Rule analysis

Flags empty if TYPE_CHECKING blocks containing only pass statements.

Fix: Removes the entire if TYPE_CHECKING: block when its body consists solely of a pass statement, preserving surrounding indentation and code structure.

8 hazards
  • Removing the block may change line numbers, affecting debuggers or stack traces that rely on exact source locations.
  • If the block contains a trailing comment after pass, the comment will be deleted along with the block.
  • In nested contexts like class or function definitions, removing the block alters the indentation depth of subsequent lines, potentially breaking syntax if mixed tabs/spaces exist.
  • When the block follows a try/except/finally clause, its removal can change the visual grouping and lead to misinterpretation of exception handling scope.
  • If the block is the only statement in a suite (e.g., a lambda or one-liner if), deleting it may result in an empty suite, causing a syntax error.
  • In async functions, removing the block could affect the perceived coroutine structure if tools inspect raw source for await placement context.
  • When the block is adjacent to a multi-line statement (e.g., with implicit line continuation), its removal may alter the boundary detection for the continued line.
  • If the block is used as a placeholder for future type annotations (common in stubs), removing it deletes intentional design intent documented via comments nearby.
