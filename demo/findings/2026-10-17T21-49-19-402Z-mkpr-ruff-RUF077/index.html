Rule analysis

Flags methods where the first parameter (receiver) has a default value.

Fix: Removes the default value expression from the receiver parameter (the first parameter of the method definition).

12 hazards
  • If the method is called directly via the class (e.g., C.m()) without providing the receiver argument, removing the default causes a TypeError due to missing positional argument.
  • If the default value is a mutable object (e.g., self=[]), removing it eliminates shared state across calls, changing behavior for callers who relied on that sharing.
  • If the default value has side effects (e.g., self=print('hi') or self=f()), removing it prevents those side effects from occurring at function definition time.
  • If the default value is used elsewhere in the method body (e.g., def f(self=None): return self is None), removing it may cause NameError if the parameter is referenced without being passed.
  • If the method is overridden in a subclass and the subclass relies on the parent's default for dispatch or behavior, removing the default breaks the override contract.
  • If the default value depends on variables from outer scope (e.g., self=x where x is defined later), removing it changes closure capture and may cause NameError if x is not defined when the method is called.
  • If the method is used in a context where the receiver is intentionally omitted and the default provides a sentinel (e.g., for optional chaining or mocking), removing it breaks that pattern.
  • If the default value is an expression that evaluates to a type or class used in annotations or isinstance checks within the method, removing it alters those checks.
  • If the method is part of an API where callers explicitly rely on the ability to omit the receiver (even if unconventional), removing the default constitutes a breaking change.
  • If the default value is a forward reference or string annotation (e.g., self="Self"), removing it may affect tools that inspect defaults for refactoring or documentation.
  • If the method contains nested functions that close over the receiver parameter and rely on its default value for correctness, removing the default alters the captured value in those closures.
  • If the default value is a decorated expression or involves complex operators (e.g., self=a+b), removing it changes evaluation timing and may affect performance or side-effect order.
