Rule analysis

Flags lines ending with a '#' character without following non-whitespace text.

Fix: Removes the trailing '#' and any whitespace immediately preceding it on the same line, leaving the rest of the line unchanged.

10 hazards
  • If the '#' is part of a string literal (e.g., `s = "abc#" #`), removing it alters the string value.
  • If the '#' is inside a byte string or f-string (e.g., `b"data#" #` or `f"{x}#" #`), the fix corrupts the literal content.
  • If the line contains a backslash continuation before the '#' (e.g., `x = 1 \ #`), removing the '#' may break the continuation if whitespace handling changes.
  • If the '#' appears in a decorator (e.g., `@decorator# #`), the fix could produce invalid syntax by merging tokens.
  • If the '#' is in a type annotation comment (e.g., `x = 1 # type: int #`), the fix removes only the last '#', potentially leaving a malformed type comment.
  • If the '#' is followed by a newline in a multi-line statement via implicit line joining (e.g., within parentheses), the fix may affect where the line breaks are interpreted.
  • If the '#' is the only content on a line used to disable a linter directive via `# noqa` but written as `# #`, the fix removes both, disabling the intent.
  • If the '#' is part of an emoji or non-ASCII symbol in a comment-like context (e.g., `x = 1 #😀 #`), the fix may leave invalid or confusing remnants.
  • If the line is otherwise blank except for indentation and `#` (e.g., ` #`), the fix removes the '#' and may leave only whitespace, which could be insignificant but alters formatting.
  • If the '#' is in a line that also contains a semicolon statement separator (e.g., `x=1; y=2 #`), the fix does not affect semantics but may mislead if the '#' was intended to start a comment.
