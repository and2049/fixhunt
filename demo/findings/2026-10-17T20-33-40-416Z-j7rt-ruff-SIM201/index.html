Rule analysis

Flags uses of 'not' followed by equality comparison ('==' operator) between two expressions.

Fix: Replaces 'not A == B' with 'A != B'

8 hazards
  • If __eq__ returns a non-boolean (e.g., int), 'not' truthiness differs from '!=' boolean result.
  • If __ne__ is overridden but __eq__ is not, '!=' may call __ne__ while original used __eq__ then 'not'.
  • If __eq__ has side effects, the single evaluation in '!=' may differ from two evaluations in 'not' and '=='.
  • If operands overlap (e.g., same variable with mutation), evaluation count change alters outcome.
  • If __eq__ returns NotImplemented, fallback to __ne__ may differ in chained vs direct call.
  • If expressions involve short-circuiting operators (e.g., 'and'), moving 'not' changes evaluation order.
  • If code relies on 'not' producing True/False for further ops, '!=' bool may differ in type-sensitive contexts.
  • If __eq__ raises exceptions, exception timing/context may differ due to evaluation order change.
