Rule analysis

Flags inline `# ruff: disable` comments without any specified error codes.

Fix: Replace the comment with `# ruff: disable[]` when no codes were provided; preserve all other text on the line including indentation and trailing whitespace/comments after the suppression marker.

12 hazards
  • The fix removes meaningful trailing content if the line had additional non-whitespace text after `# ruff: disable` (e.g., `# ruff: disable TODO`), altering program semantics by deleting that text.
  • If the suppression comment was the only content on a line, replacing it with `# ruff: disable[]` adds characters that could affect tools relying on exact line length or column counts (e.g., language server protocols).
  • In a multiline string or docstring, the literal text `# ruff: disable` is not a comment; the fix would incorrectly alter the string value, changing runtime behavior.
  • If the line contains other comments after the suppression marker (e.g., `# ruff: disable # note`), the fix preserves them but may misalign intent if the original spacing was semantically meaningful (though rare).
  • When the suppression appears in a shebang line or encoding declaration (e.g., `# -*- coding: utf-8 #- ruff: disable`), the fix breaks the validity of that special line.
  • If the file uses a custom Ruff configuration that treats `# ruff: disable` as valid via an extension or plugin, the fix enforces core Ruff behavior and may suppress intended custom handling.
  • In generated code where line numbers are referenced elsewhere (e.g., in source maps or debug info), inserting `[]` shifts subsequent line content, potentially breaking those references.
  • If the suppression comment is part of a larger token due to missing whitespace (e.g., `x=1# ruff:disable`), the fix does not add space and may produce invalid syntax like `x=1# ruff:disable[]`, which remains a comment but could confuse parsers expecting space before `#`.
  • When the suppression is the last line of the file without a newline, adding `[]` may append without a newline, affecting tools that expect final newline.
  • If the suppression comment is inside a bracketed expression split across lines (e.g., `[\n # ruff: disable]`), the fix alters the interior comment but does not affect the expression value, though it changes formatting.
  • In a file interpreted by another tool that scans for `# ruff: disable` as a feature flag (not suppression), the fix changes the token to `# ruff: disable[]`, which may not be recognized, disabling the feature flag unintentionally.
  • If the suppression comment is copied from documentation or example where the absence of codes is intentional for illustration, the fix modifies the example, making it less clear or incorrect.
