Rule analysis

The rule flags regex literals containing two or more adjacent literal space characters.

Fix: Replaces every maximal sequence of two or more consecutive literal space characters inside a regex literal with exactly one space character.

10 hazards
  • Changes meaning when spaces are significant, e.g., in patterns like '/a b/' where two spaces are required to match.
  • Breaks quantifier semantics if spaces are part of a quantified subpattern, e.g., '/(x ){2}/' becomes '/(x ){2}/', altering repetition count.
  • Alters behavior in free-spacing mode (/x flag) where literal spaces are ignored and the fix removes meaningful visual spacing.
  • Affects regexes relying on exact space counts for parsing, such as fixed-format text matchers like '/\d{3} \d{2}/'.
  • Modifies patterns using spaces as delimiters in alternatives, e.g., '/foo | bar/' becomes '/foo | bar/', changing token boundaries.
  • Impacts negated character classes containing spaces, e.g., '/[^ ] /' becomes '/[^ ] /', altering what characters are matched.
  • Disrupts tab-separated value parsers where literal spaces are significant, e.g., '/\t \t/' becomes '/\t \t/'.
  • Removes intentional formatting in complex regexes where spaces improve readability without affecting semantics, but the fix still alters the literal.
  • May break code that generates regexes via string concatenation relying on exact space counts from literals, e.g., `new RegExp('/' + pattern + '/')`.
  • Interferes with source inspection or debugging where the original literal's space count is logged or compared.
