Rule analysis

Flags unnecessary quotes in PEP 613 explicit type aliases and PEP 695 type statements when the quoted content is a valid type expression without forward references.

Fix: Removes the outer double quotes around the type expression while preserving whitespace and inner structure, converting e.g., "int | None" to int | None.

8 hazards
  • Rewriting may break code if the quoted string contains a comment, as the fix does not preserve comments inside the quotes.
  • If the type expression relies on a name only available via TYPE_CHECKING imports, removing quotes could cause a NameError at runtime.
  • In stub files, removing quotes might violate stub-only type contracts where the unquoted form is not available at runtime.
  • If the quoted expression includes a forward reference to a class defined later in the same module, the fix assumes it is defined, which may not hold during execution.
  • The fix does not account for string concatenation inside quotes (e.g., "int" "|" "None"), leaving it unchanged but potentially misleading users.
  • If the quoted string contains escaped quotes (e.g., "\"int\" |"), the fix incorrectly strips outer quotes, corrupting the expression.
  • When the type alias is used in a runtime context (e.g., isinstance), removing quotes could alter behavior if the string was intentionally used as a fallback.
  • The fix may interfere with tools that inspect source strings directly, expecting the quotes to be present for metadata or code generation.
