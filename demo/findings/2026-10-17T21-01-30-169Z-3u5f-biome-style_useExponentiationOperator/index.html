Rule analysis

The rule flags calls to Math.pow(base, exponent) where base and exponent are any expressions.

Fix: Replace Math.pow(base, exponent) with the expression base ** exponent, preserving the original formatting and whitespace around the call but inserting the infix operator between the two arguments.

12 hazards
  • If base or exponent contains a side-effecting expression like a function call, the autofix may change evaluation order because Math.pow evaluates both arguments before the call, while the ** operator evaluates left-hand side first then right-hand side, potentially altering observable behavior if the right-hand side has side effects that depend on the left-hand side's evaluation.
  • If base or exponent contains a comma expression, the autofix will incorrectly group due to the lower precedence of the comma operator compared to **, causing part of the intended argument to be excluded from the exponentiation operation.
  • If base or exponent contains yield or await expressions, the autofix may create invalid syntax because ** cannot directly contain these operators without parentheses, leading to a SyntaxError where the original Math.pow call was valid.
  • If base or exponent contains a newline without semicolon insertion protection, the autofix could trigger automatic semicolon insertion incorrectly, changing the parsing of subsequent statements.
  • If the Math.pow call appears in a context where its return value is used as a property key (e.g., computed property name), the autofix may produce invalid syntax because ** has lower precedence than the bracket operator, requiring additional parentheses that the autofix does not insert.
  • If the Math.pow call is inside a tag template literal, the autofix may break the template processing because the resulting ** expression alters how the template strings and interpolations are grouped.
  • If base or exponent contains a regular expression literal, the autofix may cause a SyntaxError because the asterisk in ** can be confused with the multiplication operator or regex quantifier depending on spacing.
  • If the call to Math.pow is actually a reference to a local variable named Math (shadowing the global), the autofix will incorrectly rewrite it as an exponentiation operation, changing the meaning entirely.
  • If the code is in a strict mode context where Math.pow is not configurable or is replaced, the autofix assumes the standard behavior, but the actual function might have custom semantics that ** does not replicate.
  • If base or exponent contains expressions with TypeScript-specific syntax (like type assertions or generics), the autofix may produce invalid JavaScript after transpilation if the rewrite interferes with those constructs.
  • If the original code had trailing comments on the Math.pow line, the autofix may drop or misplace them because it only rewrites the call expression and does not preserve comment attachment.
  • If base or exponent contains an expression that evaluates to NaN or Infinity, the behavior of ** differs from Math.pow in edge cases involving negative bases and non-integer exponents, potentially changing the result.
