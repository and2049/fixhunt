Rule analysis

Flags repeated startswith/endswith calls on the same string value combined with 'or'/'and'.

Fix: Replaces repeated startswith/endswith calls on the same value combined with logical operators by a single call with a tuple of all arguments.

10 hazards
  • If any argument is already a tuple, wrapping it in another tuple creates nested tuples causing TypeError at runtime.
  • If the repeated value expression has side effects (e.g., a function call), evaluating it once instead of multiple times changes behavior.
  • If the repeated value is a mutable object and later mutated between calls, the fix uses the original value for all checks.
  • If an argument is a variable whose type cannot be statically determined to be str, the resulting tuple may contain non-str elements causing runtime TypeError.
  • If the logical operator is 'and' and the arguments are not mutually exclusive, the fix may alter short-circuit evaluation semantics.
  • Comments attached to individual startswith/endswith calls may be lost during rewrite.
  • If the repeated value is a property with side effects, accessing it once vs multiple times changes behavior.
  • If the code relies on the specific AttributeError from a non-string object having no startswith, the fix may delay or change the error.
  • If the repeated value is a subclass of str that overrides startswith with different semantics, the fix may not preserve behavior due to tuple handling differences.
  • If an argument is a string-like object (e.g., bytes, bytearray) where startswith expects different types, the tuple may cause type mismatch errors.
