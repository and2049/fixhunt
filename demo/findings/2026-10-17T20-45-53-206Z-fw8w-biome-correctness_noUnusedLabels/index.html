Rule analysis

The rule flags labeled statements where the label is never referenced by any break or continue statement within its scope.

Fix: The autofix removes the unused label and its trailing colon, leaving only the underlying statement unchanged.

12 hazards
  • Removing a label before a block statement may change the interpretation of break/continue targets in nested loops if those inner statements rely on the outer label for control flow.
  • If the labeled statement is a function declaration, removing the label could cause a syntax error because labels are not permitted on function declarations in strict mode.
  • When the labeled statement is an empty block ({}), removing the label may drop a comment attached to the label token, altering source formatting.
  • In a labeled switch statement, removing the label could break if a nested switch uses the same label name via a continue statement (though continue doesn't apply to switch, this highlights label name reuse confusion).
  • If the label appears before a with statement, removing it might affect lexical scoping expectations in non-strict mode, though with is deprecated.
  • For a labeled debugger statement, removing the label has no semantic effect but may interfere with debugging tools that associate labels with breakpoints.
  • If the labeled statement is preceded by a line comment on the same line, the autofix may inadvertently remove that comment if it is token-attached to the label.
  • In a labeled expression statement (e.g., LABEL: x = 1;), removing the label is safe, but if the expression has side effects, the timing remains unchanged—however, tools relying on label metadata for profiling could be affected.
  • When the labeled statement is a class declaration, removing the label causes a syntax error because labels are not allowed on class declarations.
  • If the label is used as a target by a break in a dynamically scoped eval string, removing it breaks the eval's control flow (though eval is discouraged).
  • In a labeled loop containing a function with a break that closes over the label, removing the label breaks the inner function's control flow if the break is not removed (but the rule only fires when unused, so this case shouldn't occur—still, hypothetical misuse matters).
  • If the label is immediately followed by a newline and a comment on the next line, the autofix preserves the comment, but if the tool incorrectly joins lines, it could alter comment placement.
