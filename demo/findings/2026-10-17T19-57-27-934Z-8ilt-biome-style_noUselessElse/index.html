Rule analysis

Flags else blocks after if statements containing breaking statements (return, break, continue, throw), as they are unreachable.

Fix: Removes the else block and places its statements directly after the if block, dedenting them by one level while preserving their original order.

10 hazards
  • Moving a break statement out of a switch case into the enclosing loop changes which loop it breaks, altering control flow.
  • Lifting a continue statement from inside a nested loop to an outer scope may cause it to break the wrong loop or become invalid if no enclosing loop exists.
  • Hoisting a throw statement before a variable declaration in the else block could reference a variable that hasn't been initialized yet due to TDZ.
  • Extracting a return statement from an else block inside a function may skip cleanup logic in a finally block of a surrounding try statement.
  • Moving a break from an else block inside a labeled statement to an outer context may break the wrong label or become syntactically invalid.
  • If the else block contains a function declaration, moving it to the outer scope may alter hoisting behavior and create a naming conflict.
  • Comments attached to the else block or its braces may be lost or misplaced during the rewrite, affecting readability but not semantics.
  • If the if block contains a labeled break and the else block is lifted, the label may no longer be in scope for the lifted statement.
  • Lifting a statement with side effects (e.g., i++) from an else block changes the timing of execution relative to prior code in the same block.
  • In a try-finally construct, moving a return from an else block before the finally block may prevent the finally block from executing if the return was previously guarded.
