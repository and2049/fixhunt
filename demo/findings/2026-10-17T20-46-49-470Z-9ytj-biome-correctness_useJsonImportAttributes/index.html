Rule analysis

Flags imports of .json files missing the 'type': "json" attribute in their import assertions.

Fix: Adds 'with { type: "json" }' to the import statement if no with/assert clause exists, or merges 'type': "json" into an existing with/assert clause while preserving other attributes.

12 hazards
  • Rewriting 'import data from "./data.json" with { some: "value" };' to include 'type': "json" may change behavior if the runtime relies on the absence of the type attribute for non-JSON interpretation.
  • If the import is inside a conditional block, adding the assertion could alter parsing timing and cause early errors in environments that statically reject unknown attributes.
  • In bundled environments where JSON imports are transformed via plugins, adding the assertion might conflict with plugin expectations that assume raw imports without assertions.
  • If the source file has trailing comments on the same line after the import, the autofix might incorrectly place them inside the with block or drop them during rewrite.
  • When multiple imports share the same line via commas, inserting the assertion could break syntactic validity if not applied per-import.
  • In TypeScript files, adding the assertion might interfere with type declaration merging if the module augmentation depends on the original import form.
  • If the import uses an assert clause instead of with (e.g., assert { ... }), the autofix might incorrectly convert it to with, which is not supported in older environments.
  • If the JSON file is actually a symlink or mapped to a non-JSON resource via server configuration, forcing the type attribute could cause the runtime to misparse the content.
  • In environments with custom loaders that inspect the import syntax for optimization, adding the assertion might disable those optimizations.
  • If the import is part of a larger expression (e.g., tagged template), inserting the assertion could break the surrounding syntax structure.
  • When the import is decorated with inline comments specifying loader instructions (e.g., webpack), adding the assertion might conflict with or override those comments.
  • If the import statement is generated by a macro or code-mod that expects a specific shape, the injected assertion could invalidate the macro's assumptions.
