Rule analysis

Flags explicit metaclass=abc.ABCMeta usage when defining ABCs.

Fix: Replace 'metaclass=abc.ABCMeta' with inheriting from abc.ABC; remove the metaclass keyword argument and add abc.ABC as a base class.

10 hazards
  • If the class inherits from typing.Protocol, adding ABC as a base may interfere with Protocol's structural subtyping checks at runtime.
  • If the class defines __init_subclass__ that inspects bases, inserting ABC could alter subclass creation behavior.
  • If the class relies on the exact tuple of __bases__ for pickling or registration, adding ABC changes that tuple.
  • If the class uses a custom metaclass elsewhere in the hierarchy that expects ABCMeta specifically, replacing it with ABC inheritance may break metaclass resolution.
  • If the class has a docstring or comment immediately after the metaclass keyword that is tied to formatting, the rewrite may reposition or drop it during AST reformatting.
  • If the class is defined inside a function or loop where abc.ABC is not imported in scope, the fix may introduce a NameError unless the import is hoisted.
  • If the class uses starargs (**kwargs) in its definition, the fix may reorder or drop those arguments incorrectly during AST transformation.
  • If the class is part of a dynamically generated class via type() or similar, the static rewrite does not apply and may produce mismatched behavior.
  • If the class defines __classcell__ in a nested scope, adding ABC as a base could interfere with cell binding in Python 3.x.
  • If the class is used in a context where abc.ABC is shadowed by a local variable, the fix may bind to the wrong entity.
