Rule analysis

Flags functions ending with an explicit 'return' or 'return None' when they contain no other return statements.

Fix: Removes the final 'return' or 'return None' statement from the function body, preserving any trailing comment on the same line if present.

10 hazards
  • If the function contains a nested function that uses 'return' to escape to the outer function, removing the outer return may alter control flow.
  • If the 'return' statement is inside a try block and the finally block raises an exception, removing the return may change which exception propagates.
  • If the function is overridden in a subclass and the super() call relies on the implicit None return, changing the return may affect cooperative multiple inheritance behavior.
  • If the return statement is followed by a type ignore comment on the same line, removing the line may drop the ignore and cause type-checking errors.
  • If the function is part of a protocol or interface that expects an explicit return None for documentation or tooling purposes, removing it may break tooling assumptions.
  • If the return statement is the only statement in a function body and the function is used in a context where its __code__.co_flags is inspected, removing the return may change the flag set (e.g., CO_NOFREE).
  • If the function contains a late-bound closure that captures a variable defined after the return (unreachable), removing the return does not affect behavior but may mislead readers about reachability.
  • If the return statement is written as 'return (expr)' where expr is a parenthesized expression with side effects, removing it may suppress those side effects (though the rule does not fire if there are other returns, this case is prevented by the 'no other returns' condition).
  • If the function is decorated with a decorator that inspects the bytecode for the presence of a RETURN_VALUE instruction, removing the return may change the decorator's behavior.
  • If the function is invoked via a frame hack (e.g., sys._getframe) that checks f_lasti for the offset of a RETURN_VALUE, removing the return changes the last instruction offset.
