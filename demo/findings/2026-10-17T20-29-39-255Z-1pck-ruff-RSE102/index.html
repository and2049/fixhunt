Rule analysis

Flags raise statements where parentheses around a single exception argument are syntactically unnecessary.

Fix: Removes the opening and closing parentheses that directly surround the exception expression in a raise statement, leaving the inner expression unchanged.

10 hazards
  • Rewriting `raise f()` to `raise f` changes a function call to a name reference, altering runtime behavior if `f` is a function rather than a class.
  • If the parentheses contain a tuple like `raise (ValueError,)`, removing them yields `raise ValueError,` which is a syntax error due to the trailing comma.
  • When the exception expression is a subscript such as `raise Errors[0]()`, stripping parentheses results in `raise Errors[0]` which may evaluate to a non-callable, breaking implicit instantiation.
  • If the parentheses enclose a named tuple or structured expression like `raise (err := ValueError)()`, the rewrite loses the walrus assignment side-effect.
  • In contexts where the parentheses are required for line continuation or visual grouping (e.g., multi-line expressions), removing them can break parsing or alter interpretation.
  • If the parentheses contain a comment-attached expression like `raise ValueError() # inline`, the fix may drop the comment if it’s attached to the parentheses.
  • When the raised expression is a call to a property that returns a class, e.g., `raise ExcFactory.error`, the parentheses are unnecessary but the rule may not fire; however, if it did fire on a similar pattern, removing them could change binding timing.
  • If the exception is a class defined locally within a function and the parentheses are part of a larger expression (e.g., `raise (LocalError())()`), the rewrite misfires and breaks nesting.
  • In code relying on the call to trigger `__call__` logic in a metaclass or descriptor, removing parentheses prevents that invocation.
  • If the parentheses are the only thing preventing a syntax error due to ambiguous precedence (e.g., `raise a or b()` vs `raise a or b`), their removal can change meaning.
