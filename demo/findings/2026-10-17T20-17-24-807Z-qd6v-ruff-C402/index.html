Rule analysis

Flags uses of dict() wrapping a generator expression where key-value pairs are produced via tuple literals.

Fix: Rewrites dict((key, value) for ...) into {key: value for ...} by removing the dict() call and replacing the generator expression with a dict comprehension using the same key and value expressions.

10 hazards
  • If the generator expression contains a yield statement inside a nested function, rewriting to a dict comprehension may alter generator behavior and break code relying on lazy evaluation.
  • If the generator expression is used in a context where its object identity matters (e.g., passed to another function or stored), replacing it with a dict comprehension changes the object type and breaks identity checks.
  • If the key or value expression contains side effects (e.g., function calls with mutable state), changing from generator to dict comprehension alters evaluation order or timing, potentially causing different behavior.
  • If the generator expression includes asynchronous syntax (async for), the fix is invalid because dict comprehensions do not support async iteration, leading to a SyntaxError.
  • If the generator expression is part of a larger expression where operator precedence affects parsing (e.g., dict((k,v) for k,v in items) + 1), removing dict() may change how the expression is grouped.
  • If the generator expression defines a variable that is used later in the same scope (e.g., dict((k, v) for k, v in items); print(k)), the dict comprehension does not leak the loop variable, breaking downstream code.
  • If the generator expression is empty and relies on the dict() constructor to produce an empty dict, the fix still works but may interfere with debugging or introspection tools that distinguish between constructor calls and literals.
  • If the code contains a comment inside the generator expression (e.g., dict((k, # comment v) for k, v in items)), the autofix may drop or misplace it due to AST transformation limitations.
  • If the generator expression uses a tuple with more than two elements (e.g., dict((a,b,c) for a,b,c in data)), the fix incorrectly assumes pair structure and may produce invalid syntax or runtime errors.
  • If the generator expression is nested inside a lambda or conditional expression where the dict() call is necessary for correct grouping, removing it alters the meaning of the expression.
