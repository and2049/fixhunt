Rule analysis

Flags lexical declarations directly inside switch cases without block scope.

Fix: Wraps the lexical declaration in a block by adding { before and } after the declaration statement within the switch case.

8 hazards
  • The inserted block may alter automatic semicolon insertion if the original declaration lacked a terminating semicolon and the following token starts with [, (, /, +, -, or `.`, potentially changing parsing.
  • If the lexical declaration is a function declaration, wrapping it in a block makes it block-scoped instead of function-scoped, altering its visibility outside the switch but within the function.
  • Comments attached to the declaration via trailing comment syntax may be moved inside the block or misplaced if the autofix does not preserve comment attachment points.
  • In strict mode, a block-wrapped function declaration is not allowed and will throw a SyntaxError, whereas the original might have been tolerated in non-strict contexts.
  • If the switch case contains multiple statements and the fix only wraps the first declaration, subsequent statements may fall out of the intended block scope.
  • The rewrite assumes the declaration is a single statement; if it is part of a comma-separated expression or larger statement, wrapping it in a block breaks syntactic validity.
  • Labels preceding the switch case will now apply to the block rather than the declaration, potentially altering break/continue target behavior if labels were used.
  • If the declaration uses `var` (which the rule should not flag but might due to misconfiguration), wrapping it in a block does not change its function-scoping, leading to unnecessary complexity without semantic benefit.
