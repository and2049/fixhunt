Rule analysis

Flags binary comparisons where the static literal/expression appears on the left-hand side (a Yoda condition).

Fix: Swaps the left and right operands of the binary operator while preserving the operator token and all surrounding syntactic context.

12 hazards
  • Rewriting `if (\"red\" == value)` to `if (value == \"red\")` changes operator precedence when embedded in expressions like `x && \"red\" == value`, potentially altering evaluation order.
  • If the left-hand side is a getter with side effects (e.g., `if (getMagic() == value)`), swapping operands changes when the getter is invoked relative to other subexpressions.
  • When the right-hand side involves `void 0` or `undefined`, moving it left may trigger unintended global lookups in non-strict mode due to implicit property creation.
  • In `delete obj[\"prop\"] == value`, swapping operands produces invalid syntax because `delete` expects an unbound reference on its left, breaking parsing.
  • For `new Foo(5 == size)`, swapping yields `new Foo(size == 5)`, which changes argument evaluation timing if `size` is a getter with side effects.
  • In `if (\"\" + obj == value)`, moving the string literal left breaks concatenation order, yielding different intermediate values if `obj.valueOf` has side effects.
  • When the comparison is inside a `with` block, swapping operands may alter which object scope provides identifier resolution for the moved operand.
  • If the left-hand side is a comma expression like `if ((console.log(\"x\"), 0) == value)`, swapping moves the side effect (`console.log`) to a different evaluation point relative to surrounding expressions.
  • Rewriting `if (value != \"red\")` preserves `!=` but if the original relied on left-to-right short-circuiting in a larger expression like `a && \"red\" != value`, the swap changes short-circuit behavior.
  • In template literals such as ``if (`hello${world}` == msg)``, swapping operands is safe only if the template has no side effects in its substitutions; otherwise evaluation order shifts.
  • Moving a literal with attached comments (e.g., `if (\"red\" /* TODO */ == value)`) may detach or misplace those comments depending on how the formatter handles whitespace.
  • For `if ((value) == (\"red\"))`, excessive parentheses may be preserved or dropped inconsistently by the fixer, affecting readability though not semantics.
