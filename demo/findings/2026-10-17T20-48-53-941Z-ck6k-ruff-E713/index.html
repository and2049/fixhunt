Rule analysis

Flags uses of 'not' before a containment test like 'not x in y', suggesting to rewrite as 'x not in y'.

Fix: Rewrites 'not {element} in {collection}' to '{element} not in {collection}' by moving 'not' after the element and before 'in'.

10 hazards
  • If the element expression has side effects (e.g., a function call), moving 'not' changes nothing since the element is still evaluated once.
  • If the collection expression has side effects, it is still evaluated once after the rewrite, preserving order.
  • In a lambda, the rewrite preserves behavior as the element expression is unchanged.
  • In a list comprehension, the rewrite does not alter iteration or evaluation of the element expression.
  • If 'not' is part of a larger expression like 'not x in y or z', the rewrite only applies to the 'not x in y' subexpression due to operator precedence, but the autofix may incorrectly rewrite only that part if not parenthesized.
  • If the code contains a trailing comment on the same line, the autofix may not preserve it depending on implementation.
  • If 'in' is overridden as an attribute (e.g., x.in), the syntax 'x in y' would already be invalid, so the rule does not fire.
  • If the element is a tuple unpacking like 'not a, b in c', it is a SyntaxError and the rule does not fire.
  • If the code uses 'not' as a variable name (e.g., not = 5; not x in y), it is invalid syntax and the rule does not fire.
  • If the containment test is inside a string or comment, the rule does not fire as it is not executed code.
