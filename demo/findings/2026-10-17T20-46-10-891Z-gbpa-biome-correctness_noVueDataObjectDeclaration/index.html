Rule analysis

Flags Vue component `data` options defined as plain objects instead of functions.

Fix: Replaces `data: { ... }` with `data() { return { ... }; }`, preserving the original object literal exactly as the return value.

12 hazards
  • If the object contains getter properties, moving them into a function return may change evaluation timing from definition-time to call-time, altering behavior if getters have side effects.
  • If the object uses `this` references (e.g., `{ x: this.y }`), those will now be evaluated in the context of the data function call, which may differ from the original object literal evaluation context if `this` was bound differently.
  • If the object literal appears in a larger expression where its evaluation order matters (e.g., passed to another function), extracting it into a delayed return changes when side effects occur.
  • If the object contains `console.log` or other side-effecting expressions, delaying their execution until the data function is called could affect logging order or timing-dependent tests.
  • If the object is shared or referenced elsewhere (e.g., assigned to a variable before use), the fix breaks that sharing by creating a new object each time the function is called.
  • If the object uses class fields or private symbols accessed via `this`, those references may become invalid or refer to the wrong `this` after being moved into a function return.
  • If the object literal is part of a destructuring or spread operation in a larger object, isolating it into a data function return may alter how it merges with other properties.
  • If the code relies on the object being frozen or sealed at definition time, the returned object from the function may not inherit those properties unless explicitly applied.
  • If the object contains computed property names that depend on variables in scope, moving them into a function body does not change their evaluation but may affect readability or debugging.
  • If the object is defined in a non-extendable context (e.g., inside `Object.preventExtensions`), the fix does not preserve that constraint on the returned object.
  • If the data object is used in a mixin or extended component where the original object reference is expected for identity checks, replacing it with a function return breaks reference equality.
  • If the object contains `undefined` or `null` values that are relied upon for type checking, the fix preserves them but delays their availability until the data function is invoked.
