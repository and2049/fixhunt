Rule analysis

Flags Ruff-specific suppression comments using numeric rule codes instead of human-readable rule names.

Fix: Replaces numeric rule codes in Ruff suppression comments with their corresponding human-readable rule names (e.g., F401 → unused-import), preserving comment structure, spacing, and non-numeric content.

12 hazards
  • Rewriting ignore[F401] to ignore[unused-import] assumes the mapping is correct; if Ruff’s internal rule name for F401 changes or differs in a plugin, the fix may apply an incorrect or nonexistent rule name.
  • If a comment contains a code like 999 that is not a valid Ruff rule, replacing it with a fabricated name (e.g., ignore[999] → ignore[unknown]) could produce an invalid suppression that Ruff ignores or misinterprets.
  • In a disable comment like ruff: disable[F401,F841], rewriting to named rules could fail if one code maps to a name that Ruff does not recognize as a suppressible rule (e.g., a reporting-only rule), potentially leaving violations unsuppressed.
  • The fix does not preserve inline comments after the suppression (e.g., # ruff: ignore[F401] # temporary) because it may discard trailing text when reconstructing the comment, dropping meaningful annotations.
  • If the suppression comment contains non-ASCII characters or unusual whitespace (e.g., # ruff: ignore[F401 ]), the fix might normalize or drop them during parsing/reconstruction, altering the comment’s appearance or encoding.
  • In a multiline string or docstring that resembles a suppression comment (e.g., """ # ruff: ignore[F401] """), the tool might incorrectly apply the fix inside the string, corrupting the literal content.
  • If the code uses a custom Ruff plugin that assigns F401 to a non-standard rule (e.g., a project-specific lint), replacing F401 with 'unused-import' would suppress the wrong rule or fail to suppress the intended one.
  • The fix may interfere with source control or review tools if it changes comments in a way that obscures the original intent (e.g., replacing a ticket number-associated code like F401#[fix:123] with a generic name).
  • In a file with mixed tabs and spaces in comments, the rewrite might alter indentation within the comment line, potentially violating whitespace policies even though comments are usually exempt.
  • If the suppression comment is part of a larger comment block processed by a documentation tool (e.g., Sphinx), changing rule codes to names could break parsing if the tool expects numeric codes for cross-referencing.
  • The fix does not account for conditional suppression via environment variables or pragmas embedded in the comment (e.g., # ruff: ignore[F401] if DEBUG), and rewriting could break such logic if the tool strips or reorders conditional syntax.
  • If the same numeric code appears multiple times in a comment (e.g., ignore[F401,F401]), the deduplication or reordering during fix application could alter the suppression semantics if order or repetition were significant (though Ruff treats them as a set).
