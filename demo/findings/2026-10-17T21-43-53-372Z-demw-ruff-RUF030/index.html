Rule analysis

The rule flags assert statements where the second argument is a call to print(), which results in None being passed as the AssertionError message while printing to stdout.

Fix: Replace the print() call in the assert statement's second argument with its string literal argument, removing the print call and using the message directly as the assertion error message.

10 hazards
  • The print call may have side effects beyond stdout, such as flushing buffers or triggering I/O errors, which are removed by the fix.
  • If print is called with non-string arguments (e.g., print(obj)), the fix incorrectly assumes a string literal, losing the original object's representation.
  • When print uses keyword arguments like sep, end, or file, the fix drops these formatting controls, altering output behavior.
  • If the print call is part of a larger expression (e.g., print(a) or print(b)), the fix is invalid as the rule only matches simple print calls, but the shape detection might misfire.
  • The fix removes any stdout output from the print call, which may be relied upon for logging, debugging, or test output capture.
  • In rare cases where print is overridden or mocked (e.g., in unit tests), the fix breaks test expectations by removing the call entirely.
  • If the print call appears in a lambda or comprehension within the assert (though unlikely given rule constraints), the fix would incorrectly rewrite it.
  • Comments attached to the print call or surrounding whitespace may be lost during the rewrite, depending on the linter's formatting preservation.
  • If the assertion message is intended to be None (via print()), the fix changes it to a string, altering the AssertionError's args.
  • The fix assumes the print call has exactly one argument; if it has zero or multiple arguments, the rewrite is syntactically invalid or semantically wrong.
