Rule analysis

Removes unnecessary quotes from type annotations when they are made redundant by 'from __future__ import annotations' or typing-only contexts.

Fix: Strips quotation marks from type annotations that are deemed unnecessary due to postponed evaluation or typing-only context, transforming e.g., '"Bar"' to Bar while preserving surrounding syntax and whitespace.

10 hazards
  • Rewriting a quoted forward reference like '"C"' in a class method to C may fail if C is defined later in the same module and the code relies on runtime evaluation without postponed annotations.
  • Removing quotes from an annotation in a default argument like def f(x: "List[]") = [] may cause a NameError if the type is not yet defined at function definition time.
  • The fix may incorrectly unquote annotations inside string literals or comments if the linter misidentifies them as type annotations, altering non-code text.
  • In lambdas assigned to variables, removing quotes from return annotations like lambda: "int" may break if the annotation is evaluated immediately and the type is not in scope.
  • Unquoting annotations in nested scopes (e.g., inside a function) may fail if the referenced type is only defined in an outer scope and not accessible at runtime without postponed evaluation.
  • If the file lacks 'from __future__ import annotations' and the preview flag is off, removing quotes may cause runtime NameErrors for forward references that rely on deferred evaluation.
  • The fix may remove quotes from annotations in __slots__ or other special attributes where string form is required for correct interpretation by the interpreter.
  • In code that uses eval() or exec() on annotations, removing quotes may change the string passed to evaluation, altering behavior if the annotation is inspected dynamically.
  • Unquoting may break code that depends on the annotation being a string for introspection (e.g., via inspect.get_annotations()) when postponed evaluation is not active.
  • If a quoted annotation contains a trailing or leading space inside the quotes (e.g., " int "), the fix may not preserve internal whitespace, potentially changing the string value if used elsewhere.
