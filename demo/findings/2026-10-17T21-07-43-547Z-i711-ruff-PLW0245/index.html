Rule analysis

Flags uses of 'super' without parentheses when attempting to call it like a function.

Fix: Rewrites 'super' to 'super()' when followed by attribute access, subscript, or call, preserving all arguments and whitespace.

8 hazards
  • Changing 'super.method()' to 'super().method()' alters the MRO resolution if 'super' is shadowed by a local variable named 'super'.
  • If 'super' is a property or descriptor with side effects, accessing it once vs. calling it changes behavior.
  • In 'super[index]', rewriting to 'super()[index]' may fail if the super proxy object is not subscriptable.
  • For 'super(*args)' or 'super(**kwargs)', the rewrite creates a super proxy then calls it with args, which differs from calling the original 'super' callable with those arguments.
  • If 'super' is imported or aliased (e.g., 'from builtins import super as s'), the fix may incorrectly apply to the alias.
  • In nested scopes where 'super' is rebound locally, the fix ignores the local binding and always inserts parentheses.
  • Comments between 'super' and the following dot/bracket/paren may be lost or misplaced during rewrite.
  • If 'super' is used in a string or comment-like context (e.g., r'super.method'), the tool may incorrectly modify it due to faulty parsing.
