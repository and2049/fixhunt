Rule analysis

Flags function expressions without 'this' usage, generator markers, named identifiers, arguments references, or explicit 'this' type annotations.

Fix: Replaces each flagged function expression with an arrow function having the same parameters and function body, preserving formatting and comments where possible.

10 hazards
  • Rewriting a function used as a constructor with 'new' changes behavior because arrow functions cannot be instantiated and will throw TypeError.
  • If the function expression appears before its variable declaration due to hoisting, replacing it with an arrow function creates a temporal dead zone error when accessed earlier.
  • When the function is referenced via arguments.callee (e.g., for recursion), the arrow function lacks this property, breaking self-reference.
  • If the function expression is wrapped in parentheses and immediately invoked, the arrow function may parse differently due to precedence, causing syntax errors.
  • In sequences like '0, function(){}', replacing with arrow function alters comma operator evaluation if the arrow function is misparsed.
  • If the function expression is a label target (e.g., 'label: function(){}'), the arrow function cannot be labeled, causing a syntax error.
  • When the function expression is a method in an object literal and the object is used in a super() call, the arrow function's lexical this breaks method inheritance.
  • If the function expression contains a trailing comment on the closing brace, the autofix may drop it during transformation.
  • In TypeScript, if the function expression has a return type annotation like 'function(): number', removing it breaks type checking.
  • If the function expression is part of a larger destructuring pattern, the rewrite may disrupt indentation or alignment, hiding syntax errors.
