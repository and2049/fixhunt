Rule analysis

Flags isinstance/issubclass calls where the second argument is a tuple of two or more type expressions.

Fix: Replace the tuple of types in isinstance/issubclass with a PEP 604 union using the | operator, preserving parentheses only when needed for precedence.

8 hazards
  • Rewriting isinstance(x, (int,)) to isinstance(x, int |) produces invalid syntax because the union operator requires both operands.
  • If the tuple contains a forward reference as a string (e.g., 'MyClass'), the rewrite fails because strings cannot be used with the | operator in isinstance.
  • When the tuple includes a generic alias like List[int], the rewrite to List[int] | ... may be invalid at runtime if Python version < 3.9 due to missing __or__ support.
  • If the tuple contains a type variable that is not bound in the current scope, the rewritten union may resolve to a different type due to altered scoping.
  • In a context where the tuple is built dynamically (e.g., isinstance(x, (*types,))), the static rewrite is impossible and attempting it would break the code.
  • If the isinstance call appears in a lambda or comprehension, moving the union expression may alter evaluation timing if types have side effects (though rare).
  • Comments attached to the tuple or its elements (e.g., isinstance(x, (int, # comment float))) may be lost during the rewrite.
  • If the tuple is used elsewhere in the same line (e.g., in a larger expression), extracting it for rewriting may change precedence or association.
