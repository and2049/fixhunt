Rule analysis

Flags unnecessary parentheses around expressions where they do not affect precedence or grouping.

Fix: Removes the outer pair of parentheses when they enclose a single expression and are not required for operator precedence, tuple creation, or semantic clarity.

12 hazards
  • Rewriting `return (yield x)` to `return yield x` changes it from yielding a value and returning None to a syntax error due to invalid yield placement.
  • Removing parentheses in `(lambda: x)()` alters grouping, causing the lambda to be applied to `x` instead of being called first.
  • Stripping parentheses from `((x))` may break code relying on the inner parentheses for visual grouping or tooling expectations, though semantically identical.
  • In `(x,)`, removing outer parentheses yields `x,`, which is still a tuple, but if mistakenly applied to `(x)` it becomes `x`, changing a tuple to a scalar.
  • For `f((x, y))`, removing outer parentheses gives `f(x, y)`, which unpacks the tuple and passes two arguments instead of one tuple argument.
  • In `assert (condition), message`, removing parentheses around `condition` results in `assert condition, message`, which is valid, but if applied to `(assert condition), message` it would break — however, the rule does not target this shape.
  • Comments immediately after the opening parenthesis like `(# comment x)` would be lost if the autofix removes the parentheses without preserving internal formatting.
  • In a tuple assignment like `((a, b)) = ((c, d))`, removing outer parentheses gives `(a, b) = (c, d)`, which is equivalent, but if nested incorrectly could be misapplied.
  • In `raise (Exception("err"))`, removing parentheses yields `raise Exception("err")`, which is equivalent, but if the expression were more complex, precedence might matter — though the rule avoids such cases.
  • In `[(i) for i in range(10)]`, removing parentheses yields `[i for i in range(10)]`, which is equivalent, but if the parentheses were part of a larger expression like `[(i) + 1]`, removal would change meaning — however, the rule does not fire there due to presence of `+`.
  • In f-strings like `f"{(x)}"`, the rule does not apply as it targets expressions outside string contexts; applying it incorrectly would break the f-string syntax.
  • In `isinstance((x), int)`, removing outer parentheses gives `isinstance(x, int)`, which is equivalent, but if written as `isinstance((x,), int)`, removing outer parentheses yields `isinstance(x,, int)` which is invalid — however, the rule does not fire on `(x,)` as it's a tuple.
