Rule analysis

Flags redundant list() calls around iterables in for-loops.

Fix: Remove the list() constructor call while preserving its argument expression inside the for-loop header.

8 hazards
  • Rewriting list(expr) to expr changes behavior if expr has side effects evaluated multiple times due to iteration, as list() evaluates expr once before looping.
  • If expr is a generator, list() consumes it entirely while direct iteration may leave it partially consumed after loop break/continue.
  • When expr is an iterator, list() creates a snapshot; removing it risks mutation during iteration affecting results.
  • If expr returns a non-iterable, list() raises TypeError eagerly while direct iteration defers error until first iteration attempt.
  • In nested loops, removing list() may alter scoping if expr uses variables modified in outer loop iterations.
  • The fix drops any whitespace or formatting inside list() parentheses, potentially altering readability but not semantics.
  • If expr contains a trailing comma making it a tuple, list() treats it as single argument while removal may misparse in rare edge cases (though unlikely).
  • When expr is a call to a function returning self or list subclass, list() may copy while direct iteration uses original, affecting identity checks.
