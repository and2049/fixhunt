Rule analysis

The rule flags unnecessary backslash escapes inside regular expression literals where escaping has no semantic effect.

Fix: Remove the redundant backslash before a character that does not require escaping in a regex literal, preserving all other characters and flags unchanged.

10 hazards
  • Removing '\' before ']' in a character class like '/[\]]/' changes it to '/[]/', which is an empty character class and causes a SyntaxError.
  • Removing '\' before '^' at start of a character class like '/[\^abc]/' changes it to '/[^abc]/', inverting the meaning of the class.
  • Removing '\' before '-' inside a character class like '/[a\-z]/' changes it to '/[a-z]/', altering the range from literal 'a', '-', 'z' to the range 'a' through 'z'.
  • Removing '\' before '[' in a pattern like '/[\[\]]/' changes it to '/[[]]/', which matches a literal '[' instead of '[' or ']'.
  • Removing '\' before a flagged delimiter like in '/\//' (if misparsed) could break the regex if confused with comment syntax, though rare in JS.
  • Removing '\' before whitespace like '\s' in '/[\\s]/' changes it to '/[\s]/', which now matches any whitespace instead of literal backslash and 's'.
  • Removing '\' before a Unicode escape like '/\u{1F600}/' breaks it into '/u{1F600}/', which is invalid syntax and throws.
  • Removing '\' before a digit like '/\1/' in a regex changes it to '/1/', losing the backreference and matching literal '1' instead.
  • Removing '\' before a literal '}' in a quantifier like '/a\{3}/' changes it to '/a{3}/', which is valid but now means 'aaa' instead of literal 'a{3}'.
  • Removing '\' before a literal '(' like '/\(foo\)/' changes it to '/(foo)/', turning a literal match into a capturing group, altering group count and behavior.
