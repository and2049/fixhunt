Rule analysis

Flags redundant str() or float() calls around integer literals or special float string literals ('inf', '-inf', 'nan') passed to Decimal constructors.

Fix: Replaces str(integer_literal) with the integer_literal itself and float(string_literal) with the string_literal itself when the string literal is 'inf', '-inf', 'nan', or case variants, within Decimal() constructor arguments.

10 hazards
  • Rewriting Decimal(str(x)) to Decimal(x) changes behavior if x is not an integer literal (e.g., variable or expression), altering type or value.
  • Rewriting Decimal(float(s)) to Decimal(s) fails if s is not exactly 'inf', '-inf', or 'nan' (case-sensitive), producing invalid Decimal input.
  • The fix may remove necessary parentheses in complex expressions, altering precedence if the argument is part of a larger expression.
  • If the str() or float() call contains a comment (e.g., str(0 # comment)), removing it would delete the comment, violating fix safety conditions.
  • Using Decimal(float('inf')) vs Decimal('inf') may differ in signaling NaNs or context-dependent behavior, though value is same; but strict equivalence is not guaranteed across all contexts.
  • If the integer literal is part of a larger expression like Decimal(str(0)+str(1)), the fix would incorrectly apply only to part, breaking syntax.
  • The rule assumes the argument is a literal; if the integer is a named constant (e.g., ZERO), rewriting Decimal(str(ZERO)) to Decimal(ZERO) may change meaning if ZERO is not an int.
  • Rewriting could interfere with debugging or profiling if the str/float call was intentionally placed for breakpoint or side effect (though pure, still alters source structure).
  • In rare cases, float('inf') might raise in restricted environments, but str(int) never does—removing float call could hide intended error handling.
  • The fix does not account for Unicode or locale-specific number formatting; assuming ASCII literals only.
