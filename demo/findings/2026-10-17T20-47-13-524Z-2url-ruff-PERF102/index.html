Rule analysis

Flags dict.items() iteration where either loop variable is unused.

Fix: Replace dict.items() with dict.keys() when only the key is used, or dict.values() when only the value is used, preserving the used loop variable and loop body.

8 hazards
  • Rewriting 'for k, v in d.items(): ...' to 'for k in d.keys(): ...' changes behavior if 'v' is referenced later in the function due to lingering binding.
  • If the loop variable prefixed with '_' is actually used (e.g., via locals() or eval), replacing .items() with .values() removes the key binding, breaking access.
  • When the dictionary is a non-standard mapping (e.g., a custom class without .keys()/.values()), the rewrite causes AttributeError.
  • If .items(), .keys(), or .values() are overridden with custom logic (e.g., logging or filtering), the rewrite alters side effects.
  • In nested scopes, replacing .items() with .keys()/.values() may inadvertently capture outer-scope variables if the loop variable name shadows them.
  • If the loop body contains 'del v' or similar, removing the binding via .values() causes UnboundLocalError.
  • The rewrite may disrupt debugging or tracing tools that rely on the frame locals containing both key and value variables.
  • If the dictionary iteration is modified during iteration (e.g., adding/removing keys), .items(), .keys(), and .values() behave differently under mutation, altering which items are visited.
