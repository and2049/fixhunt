Rule analysis

The rule flags octal escape sequences like \251 inside string literals as they are deprecated per ES5.

Fix: Replace each octal escape sequence \ddd (where ddd is one to three octal digits) with its equivalent Unicode escape sequence \u00hh, where hh is the two-digit hexadecimal representation of the octal value.

10 hazards
  • In template literals, the autofix may incorrectly process \251 as an escape when it was intended as literal backslash followed by '251', changing the string value.
  • If the octal escape appears inside a larger string with adjacent characters, the fix could alter tokenization if the replacement introduces characters that form new escape sequences with neighboring text.
  • The fix assumes the octal value represents a Unicode code point; however, in legacy environments, octal escapes were sometimes used for byte values in binary data, and converting to Unicode escapes may change how the string is interpreted when encoded to UTF-8.
  • If the string is used in a context where it is later evaluated as code (e.g., via eval), the rewritten escape may not behave identically due to differences in how escape sequences are processed in eval vs. literal strings.
  • The autofix does not preserve leading zeros in the octal sequence (e.g., \007 becomes \u0007), which is semantically equivalent but may affect code that relies on the exact source length for parsing or metadata.
  • If the octal escape is part of a concatenated string built across multiple lines using backslash continuation, the fix could disrupt the continuation if the replacement alters line length or introduces unintended line terminators.
  • In regex literals mistakenly written as strings (e.g., "\251" used in RegExp constructor), the fix changes the string passed to RegExp, potentially altering the resulting regex pattern if the escape was meant to be a literal digit sequence.
  • If the code relies on the string's raw character count for indexing or buffer operations, the fix preserves semantics but may interfere with tools that measure string length based on source representation rather than runtime value.
  • When the octal escape appears in a string that is stringified and compared against a known literal (e.g., in snapshot testing), the fix changes the source form, causing false mismatches even if runtime values are equal.
  • If the string contains multiple octal escapes and the fix processes them sequentially, overlapping or adjacent sequences (e.g., \25\1) might be misparsed, though such sequences are invalid and unlikely to appear in practice.
