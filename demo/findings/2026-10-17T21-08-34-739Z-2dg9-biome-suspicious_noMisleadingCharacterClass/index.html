Rule analysis

The rule flags regex character classes containing grapheme clusters made of multiple Unicode code points, such as emoji sequences or accented letters formed via combining marks.

Fix: Remove the misleading multi-code-point character from the character class while preserving all other elements of the regex literal, including delimiters, flags, and surrounding pattern structure.

12 hazards
  • Removing a character from a negated character class like `[^Á]` changes the set of matched characters, potentially allowing previously excluded inputs.
  • If the multi-code-point character is part of a larger pattern such as `(Á)+`, removing it from a class breaks grouping and quantifier application.
  • In a regex used with `.test()` or `.match()`, altering the pattern may change which strings are considered matches, affecting control flow.
  • When the regex is dynamically built via string concatenation, removing the character could create an invalid pattern (e.g., unescaped bracket) if not handled in context.
  • If the regex relies on the `u` flag for proper Unicode handling, removing a character may still leave behind surrogate pairs or unpaired code points that behave incorrectly.
  • In a character class subtraction like `[\p{L}&&[^Á]]` (in future or extended syntax), removing `Á` alters the intersection logic.
  • If the regex appears in a multiline string or template literal, the edit might inadvertently affect adjacent whitespace or line terminators if not precisely targeted.
  • When the regex is used in a `split()` operation, changing the delimiter pattern alters how the string is partitioned, possibly yielding different array results.
  • If the character class is empty after removal (e.g., `[]`), the regex becomes invalid and throws a SyntaxError upon execution.
  • In a lookahead or lookbehind such as `(?=[Á])`, removing `Á` from the class changes the zero-width assertion, altering match positions.
  • If the regex contains comments (e.g., `/[Á]#comment/u`), the autofix might not preserve comment placement depending on parser representation.
  • When the same regex literal is used in multiple places, the fix applies globally, potentially breaking intended behavior in other contexts where the multi-code-point character was meant to be handled as a unit.
