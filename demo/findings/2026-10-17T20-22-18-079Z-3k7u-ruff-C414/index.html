Rule analysis

Flags unnecessary nested constructor calls like list(tuple(...)) where the inner cast/type conversion is redundant.

Fix: Replaces outer constructor call with direct application to the inner iterable argument, e.g., list(tuple(iterable)) becomes list(iterable).

10 hazards
  • If the inner call has side effects (e.g., tuple(print(x) or [])), removing it eliminates those effects.
  • If the inner call returns a non-iterable (e.g., tuple(5)), the outer call would raise TypeError while the fix may not, changing error behavior.
  • If the inner call is a generator expression with side effects, removing it alters when/whether those effects occur.
  • If the inner call defines a variable via walrus (e.g., tuple((y := [1,2]))), the fix drops that assignment, breaking later uses of y.
  • If the inner call is a lambda returning an iterable (e.g., tuple(lambda: [1,2])()), the fix changes the call semantics entirely.
  • If the inner call is a class constructor with __iter__ defined conditionally, removing it may skip __init__ side effects.
  • If the inner call appears in a larger expression where its value is used elsewhere (e.g., a = tuple(x); list(a)), the fix breaks that aliasing.
  • If the inner call is wrapped in a comment-dependent line continuation or formatting, the fix may drop or misplace comments.
  • If the inner call is part of a ternary or conditional expression, removing it may alter grouping or evaluation order.
  • If the inner call is a built-in like tuple that shadows a global, removing the outer call may change which tuple is invoked in edge cases involving nested scopes.
