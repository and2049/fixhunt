Rule analysis

Flags repeated equality comparisons like 'x == a or x == b' that can be rewritten using a membership test.

Fix: Rewrites repeated equality comparisons of the form 'expr == val1 or expr == val2 ...' into 'expr in {val1, val2, ...}' when all values are hashable, otherwise into 'expr in (val1, val2, ...)'.

8 hazards
  • The expression on the left-hand side may have side effects (e.g., a function call), causing it to be evaluated multiple times in the original but only once in the fix.
  • If any compared value is unhashable (e.g., a list or dict), the fix uses a tuple, but the original may rely on short-circuiting to avoid evaluating later values after a match.
  • The fix evaluates all values in the set/tuple upfront, which can raise exceptions during construction (e.g., division by zero in a literal) that would not occur in the original if earlier comparisons succeeded.
  • Comments attached to individual comparison operands may be lost or misplaced during the rewrite into a single expression.
  • If the left-hand expression is mutable and changed between comparisons (e.g., via aliasing), the original may see different values while the fix uses a single evaluated value.
  • In rare cases, custom __eq__ implementations may behave differently when invoked multiple times vs. once due to state changes.
  • The fix may alter operator precedence interactions if the original expression was part of a larger boolean expression relying on short-circuiting for control flow.
  • If the compared values include duplicates, the deduplication in a set may change behavior if equality is not idempotent or if duplicates had semantic meaning (though unlikely).
