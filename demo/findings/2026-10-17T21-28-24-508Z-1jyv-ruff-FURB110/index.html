Rule analysis

Flags ternary conditional expressions where the condition equals the true branch, suggesting replacement with 'or' operator.

Fix: Replace the ternary expression 'x if x else y' with the equivalent 'or' expression 'x or y'.

10 hazards
  • If the condition expression has side effects (e.g., function call), it will be evaluated once in the rewrite but twice in the original when truthy, changing behavior.
  • If the condition expression is mutable and altered between evaluations, the rewrite may observe different state.
  • If the condition expression raises an exception on second evaluation but not first, the rewrite avoids the exception while original may raise it.
  • If the condition expression returns a value that is equal but not identical to the true branch due to custom __eq__, the rewrite may produce a different object.
  • If the condition expression is a property with side effects in its getter, the rewrite invokes it once vs potentially twice.
  • If the condition expression involves logging or debugging calls with side effects, those calls may occur fewer times in the rewrite.
  • If the condition expression appears in a context where its value is used elsewhere between evaluations, the rewrite breaks that dependency.
  • If the condition expression contains inline comments, the autofix may discard them during rewrite.
  • If the condition expression is part of a larger statement where evaluation order matters for subsequent expressions, the rewrite alters sequencing.
  • If the condition expression returns a non-boolean where truthiness differs from explicit boolean conversion, the rewrite behavior diverges.
