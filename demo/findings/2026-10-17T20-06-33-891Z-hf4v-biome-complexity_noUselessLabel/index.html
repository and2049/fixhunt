Rule analysis

The rule flags labeled statements where the label is never referenced by any break or continue statement within its body.

Fix: Remove the label and colon prefix from the labeled statement, leaving only the underlying statement unchanged.

10 hazards
  • Removing a label that is referenced by a break or continue outside the labeled statement’s body changes control flow because the reference becomes unresolved.
  • If the labeled statement is a function declaration, removing the label turns it into an expression or alters hoisting behavior.
  • When the labeled statement is a block containing a `with` statement, label removal may affect identifier resolution inside `with`.
  • If the label shares a name with a variable in an outer scope, removing it could cause a break/continue to incorrectly bind to that variable via label shadowing rules.
  • In strict mode, a labeled function declaration has different semantics than an expression; dropping the label may violate early error rules.
  • If the label is used as a target for `goto`-like simulation via exceptions, removing it breaks the simulation.
  • Comments attached to the label token (e.g., `// label`) may be lost during rewriting if the tool discards leading/trailing tokens on the label.
  • When the labeled statement is the sole element of a comma expression, removing the label alters parsing precedence.
  • If the label precedes an empty statement (`label: ;`), removing it may trigger ASI issues in subsequent lines.
  • In module code, a labeled statement that exports a binding via label reference (uncommon but possible via eval) would lose that binding after removal.
