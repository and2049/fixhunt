Rule analysis

Flags trailing 'return;' statements at the end of functions where removal does not alter control flow.

Fix: Remove the trailing 'return;' statement when it is the last reachable statement in a function body.

8 hazards
  • In a finally block, removing 'return;' may allow execution to fall through and suppress an intended return value.
  • If the function is a generator, removing 'return;' may change whether it yields undefined or terminates early.
  • In an async function, removing 'return;' may alter the timing of when the promise resolves relative to microtask scheduling.
  • If the 'return;' is followed by a comment on the same line, the autofix may incorrectly remove the comment depending on tool implementation.
  • In non-strict mode, a trailing 'return;' in a function with duplicate parameter names may interact differently with arguments object behavior.
  • If the function is part of a comma-separated sequence in an expression, removing the return may affect the overall expression's value.
  • In a function with labeled statements, removing 'return;' may inadvertently allow fall-through to a labeled block that was meant to be skipped.
  • If the function is evaluated via eval() or Function constructor, removing the return may change the completion value seen by the caller.
