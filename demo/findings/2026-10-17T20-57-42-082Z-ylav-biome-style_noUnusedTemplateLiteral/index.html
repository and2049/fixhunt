Rule analysis

The rule flags template literals without interpolations or escaped characters as unused.

Fix: Replace the template literal with a string literal using single quotes, preserving the exact content inside the backticks.

5 hazards
  • If the template literal contains a backslash followed by a quote (e.g., `it\'`s`), rewriting to a single-quoted string may create an invalid escape or alter the string value due to differing escape rules.
  • If the template literal contains a backtick character (e.g., `a\(b\)`), removing backticks and using single quotes may cause syntax errors if the content includes unescaped single quotes or breaks string delimiters.
  • If the template literal is part of a larger expression like `` `Hello ${user}` + `!` ``, the autofix only applies to the unused part, but if misapplied to the whole, it would break interpolation — however, the rule only flags fully unused literals, so this is mitigated by scope.
  • If the template literal is tagged (e.g., `html`<p>text</p>`), the rule does not fire because it’s considered used via the tag, so no fix is attempted — hence no hazard from misapplying fix to tagged literals.
